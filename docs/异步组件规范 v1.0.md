# 异步组件规范 v1.0

**状态**：草案  
**关联**：kiaao v4.0 组件模型  
**前置依赖**：[组件 Context 与生命周期规范](./component-context-spec.md)

---

## 一、背景

当前 kiaao 的组件模型是严格同步的：`h(tag, props)` 调用组件函数，组件函数同步返回真实 DOM。这一模型无法处理以下场景：

- 组件需要异步获取初始数据
- 组件依赖的模块尚未加载完成
- 组件需要执行异步初始化（如权限请求、WebAssembly 加载）

本规范定义一种**无需额外 API、无需编译器、不破坏组件单次执行原则**的异步组件支持方案。

---

## 二、核心原则

**返回 Promise 即异步组件**：当组件函数返回 Promise 时，`h()` 自动识别该组件为异步组件，进行特殊处理。同步组件返回 DOM 节点，异步组件返回 Promise<DOM>，框架统一两者。

**组件函数只执行一次**：无论同步还是异步，组件函数本身只被 `h()` 调用一次。异步只是在返回 DOM 的路径上多了一个 await，而不是重新执行组件函数。

**透明包裹**：异步组件在被挂载前，框架创建一个 `<div style="display: contents">` 作为占位容器。Promise resolve 后，真实 DOM 被添加到该容器内。该容器在布局中不可见。

**与 context 方案协同**：组件实例和 `context` 在调用组件函数之前创建完毕，以参数形式传入。异步函数内的 `await` 不会影响实例归属。

---

## 三、检测方式

框架通过判断组件函数的返回值是否为 `Promise` 来确定异步组件：

```ts
const result = tag(props, context);

if (result instanceof Promise) {
  // 异步组件处理
} else {
  // 同步组件处理
}
```

这意味着以下组件形式**全部受支持**：

```js
// 1. async function
async function Comp(props, { onMount }) {
  const data = await fetch("/api");
  onMount(() => console.log("ready"));
  return <div>{data}</div>;
}

// 2. 普通函数返回 Promise
function Comp(props, { onMount }) {
  return new Promise((resolve) => {
    onMount(() => console.log("ready"));
    setTimeout(() => resolve(<div>delayed</div>), 1000);
  });
}

// 3. 手动构造的 Promise
function Comp(props) {
  return fetch("/api").then((data) => <div>{data}</div>);
}
```

所有返回 Promise 的函数均被视为异步组件，统一处理。

## 四、实现流程

```ts
if (typeof tag === "function") {
  const instance = createComponentInstance();
  const context = createContext(instance);

  const result = tag(props, context);

  if (result instanceof Promise) {
    // 异步组件分支
    const wrapper = createWrapperElement(); // <div style="display: contents">
    wrapper[INSTANCE_KEY] = instance;
    wrapper[DISPOSE_KEY] = createDisposeFn(instance);

    let disposed = false;
    onUnmount(() => {
      disposed = true;
    }); // 注册到 instance

    result
      .then((realDOM) => {
        if (disposed) return;
        // 将真实 DOM 的实例关联转移到 realDOM 上
        realDOM[INSTANCE_KEY] = instance;
        realDOM[DISPOSE_KEY] = createDisposeFn(instance);
        wrapper.appendChild(realDOM);
        triggerMount(realDOM);
      })
      .catch((err) => {
        if (disposed) return;
        console.error("[kiaao] async component error:", err);
        // 生产模式静默保留空 wrapper
      });

    return wrapper;
  } else {
    // 同步组件分支（不变）
    result[INSTANCE_KEY] = instance;
    result[DISPOSE_KEY] = createDisposeFn(instance);
    return result;
  }
}
```

## 五、生命周期

### `onMount`

- **异步组件**：`onMount` 回调在 Promise resolve 且真实 DOM 挂入 `wrapper` 后才触发。这意味着从 `mount(root, container)` 调用到 `onMount` 触发之间存在延迟。
- **同步组件**：`onMount` 在 `mount()` 的递归遍历中触发，无延迟。

### `onUnmount`

- 可以在 Promise resolve **之前**触发。此时 `wrapper` 被移除，Promise resolve 后的逻辑通过 `disposed` 标志位被跳过。
- 如果 Promise resolve 之后组件被卸载，行为与同步组件一致。

### `cleanup`

- 注册到 `context.cleanup` 的函数在组件卸载时执行，无论 Promise 是否已 resolve。这确保了资源（如定时器、WebSocket）在组件销毁时得到释放。

---

## 六、错误处理

### Promise reject

如果异步组件返回的 Promise 被 reject：

- **开发模式**：在控制台打印错误信息。
- **生产模式**：静默保留空的 `wrapper` 元素（`<div style="display: contents"></div>`）。

错误不会传播到父组件，也不会中断其他组件的渲染。这与 kiaao 的“不强保护，但提供友好提示”原则一致。

### 未来的错误边界

本规范预留 `ErrorBoundary` 组件的扩展空间。当引入错误边界后，异步组件的 reject 可被最近的错误边界捕获，提供更优雅的错误处理。

---

## 七、DOM 结构影响

异步组件在 DOM 树中多一层 `<div style="display: contents">` 包裹。其影响：

- **布局**：无影响。`display: contents` 使容器在布局中不可见，子元素如同直接挂在父元素下。
- **CSS 选择器**：
  - `:nth-child`、`:first-child`、`:last-child` 等会将包裹元素计为一个子节点。
  - 直接子代选择器 `>` 需要多穿透一层。
- **DOM 遍历**：`parentNode.children`、`previousElementSibling` 等会包含包裹元素。

开发者需知晓这一层包裹的存在。此类影响是**确定性和可预测的**。

---

## 八、嵌套异步组件

异步组件内部可以使用另一个异步组件。这与普通用法一致，不需要特殊处理：

```jsx
async function Outer(props, context) {
  const data = await fetch("/config");
  // Inner 可能是同步或异步组件，h() 会正确处理
  return (
    <div>
      <h1>{data.title}</h1>
      <Inner />
    </div>
  );
}
```

`h()` 只判断直接调用 `tag(props, context)` 的返回值。内层组件由中间函数自行处理（通过 `await` 或 `h()` 调用），不干扰外层判断。

## 九、与同步组件的差异对照

| 维度                      | 同步组件                 | 异步组件                            |
| ------------------------- | ------------------------ | ----------------------------------- |
| 返回类型                  | HTMLElement              | Promise<HTMLElement>                |
| DOM 包裹                  | 无                       | `<div style="display: contents">`   |
| `onMount` 触发            | `mount()` 递归中立即触发 | Promise resolve 后触发              |
| `onUnmount` 在 resolve 前 | 正常触发                 | 正常触发（通过标志位跳过后续逻辑）  |
| 错误处理                  | 组件函数抛出，框架不捕获 | Promise reject 被框架捕获并打印警告 |

## 十、迁移指南

### 旧写法（同步）

```js
function Comp(props) {
  // 需要在外部处理异步逻辑，或使用 lazy
  return <div>...</div>;
}
```

### 新写法（异步）

```js
async function Comp(props, { onMount }) {
  const data = await fetch("/api");
  onMount(() => console.log("ready"));
  return <div>{data}</div>;
}
```

### lazy 组件不受影响

`lazy` 是同步组件（返回 Proxy），内部异步加载完成后通过 `when` 指令渲染真实组件。`lazy` 不依赖本规范的异步组件机制。

## 十一、待定事项

1. **`onMount` 中 async 回调的并行执行**：是否限制并发数量？当前方案不限制，所有 async 回调并发执行。
2. **错误边界**：提供 `ErrorBoundary` 组件以优雅处理异步组件错误。
3. **SSR 中的异步组件**：`renderToString` 目前是同步的，不支持 Promise 组件。异步组件的 SSR 方案待定。
4. **异步状态原语**：探索用信号标准化表达 loading/error/data 状态的 API，与 `when` 映射表配合使用。
