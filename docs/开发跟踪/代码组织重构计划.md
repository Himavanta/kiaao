## 六、`createRouter` — 78 行

**文件**：`src/router/index.ts:83`
**当前结构**：一个函数内定义所有内部函数（navigate、RouterView、Link、updateParams）+ 初始化逻辑

### 拆分方案

`createRouter` 本身的 78 行大部分是内部函数定义。每个内部函数本身通常 10-15 行，**问题不在于函数太大，而在于所有逻辑挤在一个作用域内**。建议：

| 提取为              | 方式           | 理由                                            |
| ------------------- | -------------- | ----------------------------------------------- |
| `navigate(path)`    | 保留为内部函数 | 引用闭包 `setPath`，10 行                       |
| `RouterView(props)` | 保留为内部函数 | 引用闭包 `defaultFallback` 等，15 行            |
| `Link(props)`       | 保留为内部函数 | 引用闭包 `navigate`，20 行                      |
| `updateParams()`    | 保留为内部函数 | 引用闭包 `setCurrentParams`、`getSearch`，10 行 |

实际上 `createRouter` 的内部函数已经职责分离，真正问题是 `createRouter` 本身的逻辑线过长（从创建信号到注册 popstate 到定义 4 个函数到初始化参数到返回对象）。建议将 `createRouter` 拆分为：

1. `createRouter` — 主流程（约 25 行）
2. 内部函数 `navigate`、`RouterView`、`Link`、`updateParams` 调整为模块级函数，通过参数传入依赖

或保持内部函数但将 `createRouter` 按逻辑段分段：

```
createRouter
├── 初始化信号和 popstate 监听
├── 定义 navigate
├── 定义 RouterView
├── 定义 Link
├── 定义 + 初始化 updateParams
```

## 边界情况与注意事项

1. **`h()` 的拆分可能影响类型签名**：`handleDirectiveMode` 等返回 `Element`，需要确认类型一致性
2. **`sync()` 嵌套在 `renderEach` 内**：访问闭包变量（`nodeMap`、`itemSignalMap`、`anchor`、`container`、`childFn`、`keyFn`）。提取时需要将这些作为参数传入，或提取为 `renderEach` 内部仍然嵌套但更小粒度的函数
3. **`createRouter` 的内部函数**：`navigate`、`RouterView`、`Link`、`updateParams` 都引用 `createRouter` 的闭包变量。提取为模块级函数需要改为参数传入，改变较大。可先保持内部函数但缩小 `createRouter` 主体
4. **循环拆分 `processChildren`**（31 行）：仅刚过 30 行阈值。如需拆分，可将 `isUse` 分支提取为 `createReactiveTextNode(child)`
5. **测试不受影响**：拆分后导出相同 API，内部重构不影响公共接口
