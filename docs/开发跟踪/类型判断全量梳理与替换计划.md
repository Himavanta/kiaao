| `isNil(v)`      | `v == null`                       | null/undefined       |
| `isNotNil(v)`   | `v != null`                       | 非 null 非 undefined |

## 二、需要新增的守卫（4 个）

```ts
export const isUndefined = (v: any): v is undefined => v === undefined;
export const isDefined = <T>(v: T): v is Exclude<T, undefined> => v !== undefined;
export const isMap = (v: any): v is Map<any, any> => v instanceof Map;
export const isSet = (v: any): v is Set<any> => v instanceof Set;
```

`isSVGElement` 不单独添加——`el instanceof SVGElement` 只出现一次，且 `SVGElement` 是标准 DOM 类型，保持 `instanceof` 更清晰。

## 四、特殊场景说明

### 场景 A：`isObject` 收窄后动态属性丢失

`isObject(props)` 将类型从 `any` 收窄到 `object`，此时 `props.key` 或 `props[key]` 动态访问报错。

涉及位置：`ssr-serialize.ts:61/70`、`props.ts:112`

**方案**：这些位置保留 `typeof props !== "object"` 模式。`isObject` 守卫适用于"判断后只读不写"的场景。

### 场景 B：`isObject` + `as` 转型

`ssr-serialize.ts:37`：`typeof val === "object" && val !== null` 后接 `serializeCssText(val)` 要求 `Record<string, string|number>` 类型。

**方案**：`isObject(val)` 后加 `as Record<string, string|number>`。

### 场景 C：环境检测 `typeof x !== "undefined"`

`lazy.ts:24`、`when.ts:57` 检查 `document`/`console` 是否定义。

**方案**：新增 `isDefined(v)` 守卫。
