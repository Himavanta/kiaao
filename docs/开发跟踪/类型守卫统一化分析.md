# 类型守卫与工具函数统一化分析 v2

**问题**：类型判断、数组处理、参数归一化等通用逻辑散落各处，缺乏统一封装。

---

## 一、现有散落模式全量梳理

### 1.1 高频类型守卫（重复 2 次以上）

| 模式                      | 出现次数 | 涉及文件                                                               |
| ------------------------- | -------- | ---------------------------------------------------------------------- |
| `x instanceof Node`       | 11       | h.ts, when.ts, process-children.ts, ssr-helpers.ts, portal.ts, each.ts |
| `typeof x === "function"` | 15+      | 所有文件                                                               |
| `typeof x === "string"`   | 8+       | serialize, props, ssr-helpers 等                                       |
| `typeof x === "object"`   | 10+      | serialize, props, ssr-render, h.ts                                     |
| `typeof x === "boolean"`  | 5+       | 散落                                                                   |
| `typeof x === "number"`   | 4        | each.ts, ssr-helpers                                                   |
| `x instanceof Promise`    | 2        | h.ts, ssr-render.ts                                                    |
| `x instanceof Element`    | 1        | h.ts                                                                   |
| `Array.isArray(x)`        | 5+       | process-children, ssr-render, portal, each, jsx-runtime                |

### 1.2 重复的列表/数组操作模式

| 模式                                             | 次数 | 涉及文件                        |
| ------------------------------------------------ | ---- | ------------------------------- |
| `children.length === 1 ? children[0] : children` | 2    | h.ts（directive + component）   |
| `children.flat(Infinity)`                        | 1    | h.ts（directive）               |
| `children[0]` 直接索引                           | 8+   | when.ts, ssr-render.ts, each.ts |
| 循环 `for (const x of arr)`                      | 10+  | 几乎所有文件                    |

### 1.3 单文件专用但可提取的工具

| 函数                     | 所在文件         | 可提取理由                      |
| ------------------------ | ---------------- | ------------------------------- |
| `isPlainObject(v)`       | ssr-helpers.ts   | 通用 JS 判断，非 SSR 专属       |
| `stripDirectives(props)` | ssr-serialize.ts | 通用 props 清洗                 |
| `createSafeSignal()`     | h.ts             | 与 directive.ts 的 use 逻辑相似 |

### 1.4 已发现的具体问题

1. **`isPlainObject` 冗余**: `!isSSRSafe(v)` 永远为 true（SSR_MARKER 是局部 Symbol）
2. **`typeof "object"` 缺少统一 null 防护**: 2 处依赖外层短路而非内联检查
3. **`children` 归一化重复**: `children.length === 1 ? children[0] : children` 在 h.ts 中出现 2 次

## 二、建议方案

### 2.1 新建 `src/utils/type-guards.ts`

```ts
// ── 类型守卫（提供 v is T 类型收窄）──

export const isNode = (v: any): v is Node => v instanceof Node;
export const isElement = (v: any): v is Element => v instanceof Element;
export const isPromise = (v: any): v is Promise<any> => v instanceof Promise;
export const isFunction = (v: any): v is Function => typeof v === "function";
export const isString = (v: any): v is string => typeof v === "string";
export const isNumber = (v: any): v is number => typeof v === "number";
export const isBoolean = (v: any): v is boolean => typeof v === "boolean";
export const isObject = (v: any): v is object => typeof v === "object" && v !== null;
```

### 2.2 新建 `src/utils/helpers.ts`

```ts
// ── 列表/参数归一化 ──

/** 单元素数组展开：`[el]` → `el`，多元素保持 */
export const normalizeChildren = <T>(children: T[]): T | T[] =>
  children.length === 1 ? children[0] : children;
```

### 2.3 修复 `isPlainObject`

移除冗余的 `!isSSRSafe(v)` 检查。

### 2.4 保留在原位置的项目特定守卫

| 守卫            | 理由                                    |
| --------------- | --------------------------------------- |
| `isUse`         | 与 `Getter<T>` + `REACTIVE` Symbol 绑定 |
| `isDirective`   | 与 `DIRECT_KEY` Symbol 绑定             |
| `isSSRSafe`     | 与 `SSR_MARKER` Symbol 绑定             |
| `isVoidElement` | 与 `VOID_ELEMENTS` Set 绑定             |
| `isConnected`   | 简单的 DOM 代理                         |

## 四、不受益（保持原样）

| 模式                                 | 原因                             |
| ------------------------------------ | -------------------------------- |
| `typeof x === "string"`              | 已足够简短，不提供额外 null 安全 |
| `typeof x === "boolean"`             | 同理                             |
| `typeof x === "number"`              | 同理                             |
| `Array.isArray(x)`                   | 已经是标准 API 名                |
| `Object.keys()` / `Object.entries()` | 标准 API，包装无意义             |
