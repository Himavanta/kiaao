# 信号与常规函数类型混淆审查跟踪

**问题**：信号 getter（`use()` 创建的 `() => T`）和常规函数在运行时都是函数，但语义完全不同。框架核心需要正确区分二者，否则可能出现"把普通函数当成信号订阅"或"把信号当成普通函数调用"等错误。

---

## 审查范围

全量扫描 `src/` 下的类型签名，寻找以下模式：

| 模式                           | 风险                                   |
| ------------------------------ | -------------------------------------- |
| `() => any` / `() => T`        | 无法区分是信号 getter 还是普通工厂函数 |
| `Function` 作为类型            | 完全丢失信号/函数区分                  |
| `: any` 参数但实际可能传入信号 | 当前未经类型守卫使用可能出错           |
| `Getter<T>` 与 `() => T` 混用  | Getter 有 brand symbol，但结构上兼容   |

---

## 类型工具

`src/reactive/types.ts` 中现有：

```ts
export interface Getter<T> {
  (): T;
  readonly [GETTER_BRAND]: true;
}
```

`Getter<T>` 有 brand symbol（仅类型层面，运行时不存在）。可以用于标注"这是一个信号 getter，不是普通函数"。

`src/reactive/core.ts` 中：

```ts
export function isUse(v: any): v is Getter<any> { ... }
```

需要在需要区分信号与普通函数的地方使用类型守卫。

---

## 逐项审查

### 1. `props.ts` — `setProp` 的 `value: any`

**文件**：`src/dom/props.ts:13`
**代码**：`export function setProp(el: Element, rawKey: string, value: any): void`
**风险**：`value` 可以是信号 getter（如 `class={signal}`），但本函数处理的是"单次设置"，信号 getter 已在 `setProps` 中被过滤（通过 `isUse(value)` 提前创建派生）。
**判定**：✅ `setProps` 已正确处理信号分支，`setProp` 接收的 `value` 不会是信号。

---

### 2. `process-children.ts` — `processChildren` 的 children 类型

**文件**：`src/dom/process-children.ts:8`
**代码**：`export function processChildren(children: any[]): Node[]`
**风险**：`children` 数组元素可以是 `string`、`number`、`Node`、**信号 getter**、布尔值。函数内用 `isUse(child)` 区分信号。
**判定**：✅ `any[]` 合理——需要容纳多种类型，且有类型守卫。

---

### 3. `directives.ts` / `each.ts` — `childFn: (item: any, index: number, key: any) => any`

**文件**：`src/dom/each.ts:117`
**代码**：`childFn: (item: any, index: number, key: any) => any`
**风险**：`item` 参数是一个信号 getter（`() => T`），但类型标注为 `any`，调用方不知道它是个信号。
**判定**：🟡 应用 `Getter<any>` 标明 `item` 是信号 getter，而非任意值。

---

### 4. `directives.ts` / `when.ts` — `children[0]` 惰性函数

**文件**：`src/dom/when.ts`
**代码**：`const isLazy = ... typeof children[0] === "function" && !isUse(children[0])`
**风险**：通过运行时 `!isUse()` 检查来区分"惰性函数"和"信号 getter"，但类型上没有区分。
**判定**：✅ 运行时区分，类型上 `children[0]` 是 `any`，已用 `unknown` 收窄。

---

### 5. `renderEach` 中 `eachFn` 参数

**文件**：`src/dom/each.ts:119`
**代码**：`eachFn: (() => unknown) | (() => unknown[])`
**风险**：`eachFn` 可能是一个信号 getter（此时 `isUse(eachFn)` 为 true），也可能是一个普通函数。类型上未标明。
**判定**：🟡 应使用 `Getter<T> | (() => T)` 区分信号与常规函数。

---

### 6. `toValue` 的参数类型

**文件**：`src/reactive/core.ts:48`
**代码**：`export function toValue(v: any): any`
**风险**：`v` 可以是信号 getter 或任意值。函数内通过 `isUse(v)` 区分。类型 `any` 过于宽松，但 `Getter<T> | T` 类型推导复杂。
**判定**：✅ 设计如此——统一的"解包 API"。

---

### 7. `props` 中的信号值传递

**文件**：`src/dom/props.ts:80`
**代码**：`if (isUse(value)) { ... } else { setProp(el, key, value); }`
**风险**：JSX 中传递信号给 DOM 属性（`class={signal}`），框架自动创建派生绑定。`setProps` 中已用 `isUse` 分支处理。
**判定**：✅ 已正确处理信号分支。

---

### 8. `hSSRWhenTag` 中 `branchFn` 调用

**文件**：`src/dom/ssr-render.ts:60`
**代码**：`const branchFn = map[whenVal]; if (branchFn) { const inner = renderSSRChild(branchFn()); }`
**风险**：`branchFn` 从映射表中取出，类型为 `() => any`。如果用户误传入信号 getter 到映射表值，`branchFn` 会被调用执行（`branchFn()`），但信号 getter 被当作普通函数调用时行为可能不对——会返回当前值，这不一定是期望的渲染结果。
**判定**：🟡 映射表的值应为普通工厂函数，不应是信号。应为 `Record<string, () => any>` 且文档说明。

---

### 9. `when.ts` 中 `renderWhenLazyMode` 的 `childFn`

**文件**：`src/dom/when.ts:95`
**代码**：`function renderWhenLazyMode(el: Element, childFn: () => any, show: boolean, elseFn: ...)`
**风险**：`childFn` 是惰性渲染函数。如果用户误传入信号 getter，`childFn()` 调用会返回当前信号值而不是创建新内容。但检测模式 `isLazy` 中已有 `!isUse(children[0])` 守卫。
**判定**：✅ 运行时有守卫，类型上 `childFn: () => any` 合理。

---

### 10. `createWhenElement` 的 `elseFn`

**文件**：`src/dom/when.ts`
**代码**：`elseFn?: () => any`
**风险**：`elseFn` 是一个工厂函数，只有当 `when` 条件为 false 时调用。如果用户传入信号 getter，`elseFn()` 会被调用并返回当前值。
**判定**：✅ `elseFn: () => any` 正确——它必须是工厂函数。

---

### 11. `Mount` / `Unmount` 回调的类型

**文件**：`src/dom/component.ts`
**代码**：`mountCallbacks: (() => void)[]`
**风险**：这些是生命周期回调，不应是信号 getter。当前 `() => void` 正确。
**判定**：✅ 正确。

---

### 12. `jsx-runtime/index.ts` — `children` 类型

**文件**：`src/jsx-runtime/index.ts`
**代码**：`function normalizeChildren(children: any): any[] | undefined`
**风险**：JSX children 可以是信号 getter。此处 `any` 合理，因为 JSX 的灵活性。
**判定**：✅ 合理。

---

## 总结

| 判定 | 数量 | 说明 |
| --------- | ---- | -------------------- | ------ |
| ✅ 合理 | 10 | 有类型守卫或正确使用 |
| 🟡 可改善 | 2 |
| 🛠 已修复 | 2 | 见下方 | 见下方 |
| 🔴 不合理 | 0 | — |

### 🟡 建议改善

**1. `each.ts` — `childFn` 的 item 参数应为 `Getter<T>`**

```ts
// 当前
childFn: (item: any, index: number, key: any) => any;
// 建议
childFn: <T>(item: Getter<T>, index: number, key: any) => any;
```

文档中已说明 `item` 是信号 getter，但类型上未体现。使用 `Getter<T>` 能明确表达"这是一个响应式引用"。

**2. `renderEach` 的 `eachFn` 应区分信号与普通函数**

```ts
// 当前
eachFn: (() => unknown) | (() => unknown[])
// 建议
eachFn: Getter<unknown> | Getter<unknown[]> | (() => unknown) | (() => unknown[])
```

但 Getter 在结构上与 `() => T` 完全相同（仅多了类型层面的 brand），实际效果相同。此改善主要起文档作用。
