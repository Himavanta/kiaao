# 类型系统优化分析

> 日期：2026-06-23
> 在完成 `Props` / `NullableProps` 统一后的遗留类型优化机会

---

## 1. `children` 类型统一

`children` 在多个函数中重复定义为 `any[]`。提取共享类型可以让语义更清晰，也便于未来约束。

**涉及位置：**

| 文件                  | 位置                                                                       |
| --------------------- | -------------------------------------------------------------------------- |
| `h.ts`                | `h()` 重载、`handleDomMode`、`handleDirectiveMode`                         |
| `component.ts`        | `mergeResults`、`handleComponent`                                          |
| `directives.ts`       | `createWhenElement` options、`createEachElement` options、`detectWhenMode` |
| `process-children.ts` | `processChildren` 签名                                                     |

**建议：** 在 `types.ts` 增加 `type Children = any[]` 或更精确的类型。但 `children` 实际可包含 `Node`、`HResult`、`Signal`、`string`、嵌套数组等——`any[]` 是最诚实的选择。提取类型别名的主要收益是统一修改入口和文档化。

**优先级：** 低（纯别名，无类型安全收益）

---

## 2. `(() => void)[]` 清理函数数组

`cleanups: (() => void)[]` 在全库重复出现约 10 次。

**涉及位置：**

- `types.ts`: `HResult.cleanups`、`ProcessChildrenResult.cleanups`、`Owner.cleanups`
- `h.ts`: `handleDomMode` 的 `orphanCleanups`
- `directives.ts`: `createWhenElement`/`createEachElement` 参数
- `props.ts`: `setProps` 参数

**建议：** 提取为 `type CleanupFn = () => void` 和 `type Cleanups = CleanupFn[]`。

```ts
export type CleanupFn = () => void;
export type Cleanups = CleanupFn[];
```

**收益：** 中等——减少重复，一处在 `Owner` 中已使用但未命名。

## 3. Motion 动画组件泛型化

`create-group-motion.ts` 的函数签名全用 `any[]` 操作数组，但语义上是同类型元素的数据。

**当前：**

```ts
function findRemovedKeys(
  oldArray: any[],
  newArray: any[],
  keyFn: (item: any, index: number) => any,
): any[];
```

**建议：**

```ts
function findRemovedKeys<T, K>(
  oldArray: T[],
  newArray: T[],
  keyFn: (item: T, index: number) => K,
): K[];
```

**收益：** 高——Motion 是用户直接调用的 API，泛型让用户数据保持类型安全。

## 4. `SignalState<T>` 的 `set` 属性已删除但历史残留

在 Signal API 统一重构中移除了 `DefinitionState.set`，但 `DerivationState` 仍然有：

```ts
export interface DerivationState<T> {
  // ...
  subs: Set<DerivationState<any>>; // 这里的 any 可改为 T
}
```

`Set<DerivationState<any>>` 在 `types.ts:80` 和 `83` 使用了 `any` 而不是 `T`。这是正确的——派生信号可以被子派生信号订阅，子派生可能计算不同类型的值。保持 `any`。

**收益：** 无（设计如此）

---

## 5. `RenderAdapter` 接口中 `handler: Function`

```ts
addEventListener(el: unknown, type: string, handler: Function): void;
removeEventListener(el: unknown, type: string, handler: Function): void;
```

`Function` 类型不够精确。但这是适配器接口，不同平台的 event handler 签名不同（DOM 是 `EventListener`、Lynx 可能不同）。用 `Function` 是最通用的选择。保持。

**收益：** 无（适配器层需要通用性）

---

## 6. `appOwner` 在 `create-app.ts` 的赋值

当前：

```ts
const appOwner = isHResult(hr) ? hr.owner : null;
const nodes: Node[] = isHResult(hr) ? [...hr.nodes] : [];
```

`h()` 始终返回 `HResult`，但代码用 `isHResult(hr)` 守卫。可以简化为：

```ts
const appOwner = hr.owner;
const nodes = [...hr.nodes];
```

但考虑到 `h()` 的类型重载在边界情况下可能改变，当前守卫是防御性编码。保持。

**收益：** 极小（简化 2 行）

---

## 7. `children: any` 在 JSX 运行时

`jsx-runtime/index.ts` 的 `normalizeChildren` 参数为 `children: unknown`——这是正确的，因为 JSX children 可以是任何类型。

---

## 8. 可考虑的详细类型

| 概念                   | 当前类型                  | 建议             | 优先级 |
| ---------------------- | ------------------------- | ---------------- | ------ |
| `CleanupFn`            | `() => void` 重复 10+ 处  | 提取别名         | 中     |
| `Cleanups`             | `(() => void)[]` 重复多处 | 提取别名         | 中     |
| Motion 数组操作        | `any[]`                   | 泛型 `T[], K[]`  | 高     |
| `processChildren` 参数 | `children: any[]`         | 提取别名         | 低     |
| `Owner.elements`       | `Set<unknown>`            | 保持（跨平台）   | —      |
| `RenderAdapter` 返回值 | `unknown`                 | 保持（抽象）     | —      |
| `h()` `tag` 参数       | `any`                     | 保持（多态分发） | —      |
