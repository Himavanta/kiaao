# 开发体验增强：错误警告与保护机制

> 任务：通过大量测试发现框架的各种崩溃可能性及静默失败路径，然后增加警告和保护机制。
> 目标：让开发者在遇到问题时能立即定位到原因，而非面对白屏或无反馈。

---

## 方法论

1. **构造极端/非法场景** → 观察框架行为
2. **记录**崩溃 or 静默失败 or 错误无上下文
3. **分类**决定加警告 or 加保护 or 文档说明
4. **实现**警告/保护，附带 `new Error()` 栈追踪

---

## 测试范围

| 模块                        | 重点关注                                            |
| --------------------------- | --------------------------------------------------- |
| **reactive/core.ts**        | 非法参数、循环依赖、已销毁后操作、异步中 setter     |
| **dom/h.ts**                | 非法 tag、非法 props、组件函数抛错、异步组件竞态    |
| **dom/component.ts**        | 重复 mount/unmount、mount 后立即操作、嵌套异常      |
| **dom/directives.ts**       | each 源非法值、key 重复、when+each 冲突、void 元素  |
| **dom/props.ts**            | 未知事件名、非法属性值、响应式属性 + 非响应式值切换 |
| **dom/process-children.ts** | 非法子节点类型（Symbol、BigInt）、循环引用          |
| **dom/portal.ts**           | 目标元素不存在、重复 portal、目标被外部移除         |
| **dom/lazy.ts**             | 加载器抛错、加载器返回非组件、多次加载              |
| **dom/ssr-helpers.ts**      | SSR 中调用 DOM API、异步组件、生命周期操作          |
| **router/index.ts**         | 路由匹配失败、navigate 到非法路径、重复注册         |

## 发现与结论

### A. 真实未捕获崩溃（需加保护）

| #   | 场景                              | 文件            | 当前行为                           | 建议保护                                                         |
| --- | --------------------------------- | --------------- | ---------------------------------- | ---------------------------------------------------------------- |
| A1  | `derive` 初始计算抛错             | `core.ts`       | 传播到 `use()` 调用处              | 初始计算包 try-catch，输出 `new Error("derive error")` 含栈      |
| A2  | `each` 的 `childFn` 抛错          | `directives.ts` | 传播到 `h()`                       | renderEach 中 `childFn` 调用包 try-catch，跳过当前 item          |
| A3  | `h()` 组件模式 tag 抛错           | `h.ts`          | 传播到 `h()` 调用者                | 保持抛出让 catch，但在 dev 模式下包 try-catch 输出 `new Error()` |
| A4  | `onUnmount` 回调中抛错            | `component.ts`  | safeCall 捕获并 console.error      | ✅ 已有，但缺少谁触发的上下文                                    |
| A5  | 派生 setter 调用时 computeFn 抛错 | `core.ts`       | `recomputeDerivation` 中的错误传播 | 包 try-catch，避免影响其他派生                                   |

### B. 静默失败（需加警告）

| #   | 场景                         | 文件            | 当前行为               | 建议警告                                                          |
| --- | ---------------------------- | --------------- | ---------------------- | ----------------------------------------------------------------- |
| B1  | `mount()` 容器非空           | `component.ts`  | 直接 append            | `new Error("mount target already has child nodes")`               |
| B2  | `unmount()` 重复调用         | `component.ts`  | disposeNode 第二次跳过 | `console.warn("[kiaao] component already unmounted")`（dev 模式） |
| B3  | `each` 源为 `null/undefined` | `directives.ts` | 渲染空列表             | `console.warn("each source is null/undefined")`                   |
| B4  | Portal 目标不存在            | `portal.ts`     | 返回注释节点           | 无警告 ✅ 行为预期，但可加 dev 提示目标选择器                     |
| B5  | 非法 tag 名                  | `h.ts`          | 返回注释占位           | ✅ 已有占位，可加 dev 警告"invalid tag"                           |

### C. 合理行为（无需改动）

| #   | 场景                              | 理由                                                     |
| --- | --------------------------------- | -------------------------------------------------------- |
| C1  | `when={undefined}` = 没传 when    | JSX/JS 惯例，undefined prop 应忽略                       |
| C2  | 信号在组件卸载后 setter           | 信号独立于 DOM，setter 永远可用。订阅已被清理，不影响 UI |
| C3  | 节点移动后再次 mount              | `append` + `triggerMount` 安全，INITIALIZED_KEY 防重复   |
| C4  | 各非法子节点类型（Symbol/BigInt） | `String()` 转换正常显示                                  |
