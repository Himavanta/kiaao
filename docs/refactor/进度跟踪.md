## 阶段一：Core Types + REACTIVE + 辅助函数

**目标**：建立新类型系统骨架，`isUse`/`toUse`/`toVal` 可用，`use` 尚不可用。

### 改动内容

#### `src/core/types.ts`

- ✅ `REACTIVE` Symbol — 语义从「纯标记」变为「指向内部状态对象」
- ✅ 内部状态类型（供 TS 参考，实际用 interface）
  - `DefinitionState<T>`: `{ value: T; subs: Set<any>; set: Setter<T> }`
  - `DerivationState<T>`: `{ deps; cachedValue; subs; computeFn; set; stops; stop }`
- ✅ `Getter<T>` — 删除选择器重载，简化为 `() => T`
- ✅ `Setter<T>` — 保持不变
- ❌ 删除 `ReactiveFunction`（不再需要）
- ❌ 删除 `STOP_KEY`（旧 derive 内部使用）
- ✅ 保留 `DISPOSE_KEY`、`INSTANCE_KEY`、`INITIALIZED_KEY`、`DISPOSED_KEY`、`LOCAL_EFFECTS`、`SSR_COMPONENT`
- ✅ 保留 `ComponentInstance`

#### `src/core/runtime.ts`

- ✅ 新增 `isUse(v: any): boolean` — 检查 `v?.[REACTIVE] !== undefined`
- ✅ 新增 `toUse<T>(v: T): [Getter<T>, Setter<T>]`
  - 若 `isUse(v)` → 返回 `[v, v[REACTIVE].set]`
  - 否则 → 等价于 `use(v)`（等阶段二完成）
- ✅ 新增 `toVal(v: any): any` — `isUse(v) ? v() : v`
- ⏳ 新增 `use`（留空壳或异常抛出不实现，次阶段完成）
- ✅ 保留：`setRenderMode`/`getRenderMode`、`componentStack`、`currentComponent`/`pushComponent`/`popComponent`/`createComponentInstance`
- ❌ 待删：`define`、`effect`、`derive`（阶段四执行）

### 风险 / 注意事项

- `isUse` 依赖 `REACTIVE` Symbol 完成，两者必须同时发布
- `toUse` 在已有信号分支下依赖 `state.set` 存在，因此 `use` 的定义模式须将 `set` 挂载到 `state`
- `toUse` 在非信号分支下内部调用 `use(v)`，阶段一先写占位实现

## 阶段二：`use` 完整实现

**目标**：`use` 的定义模式和派生模式可用，更新传播正确。

### 改动内容

#### `src/core/runtime.ts` — `use` 函数

**定义模式** `use(initialValue)`：

- 创建 `DefinitionState`
- `getter` 挂载 `[REACTIVE] = state`
- `setter`：`value !== oldValue` → 通知 `subs`
- `state.set = setter`

**派生模式** `use(...deps, computeFn)`：

- 参数解析：`const [func, ...deps] = ars.reverse()`
- 创建 `DerivationState`，遍历 `deps` 将自身注册到各依赖的 `subs`
- 初始执行 `computeFn(undefined)` 建立缓存
- `setter` 逻辑：触发 `computeFn(value)`，短路判断
- 上游变化触发：`computeFn(undefined)` → 短路 → 递归下游
- 返回 `[getter, setter]`，getter 挂载 `[REACTIVE] = state`
- `state.stop` = 清理函数（遍历 `stops` 从各依赖的 `subs` 移除自己）
- `state.set` = setter

**类型重载**（TS）：

```ts
function use<T>(initialValue: T): [Getter<T>, Setter<T>];
function use<T>(...deps: [...Signal[], (v?: any) => T]): [Getter<T>, Setter<T>];
function use(...deps: [...Signal[], (v?: any) => void]): [Getter<void>, Setter<void>];
```

**开发模式校验**：

- 最后一个参数不是函数 → 警告并返回
- 最后一个参数是信号 → 警告
- 依赖中存在非信号 → 警告并过滤

### 关键实现细节

| 场景             | computeFn 参数           | 触发条件                 |
| ---------------- | ------------------------ | ------------------------ |
| 创建时初始执行   | `undefined`              | 同步                     |
| 上游依赖变化     | `undefined`              | `setter()` 或上游 setter |
| 派生 setter 调用 | `setter(value)` 传入的值 | `setValue(42)`           |

短路逻辑：`newResult === cachedValue` → 不通知下游。

## 阶段三：适配 `h()` 及相关模块

**目标**：框架核心渲染链路使用新信号系统。

### 改动内容

| 文件                  | 改动                                                                                   |
| --------------------- | -------------------------------------------------------------------------------------- |
| `h.ts`                | `IS_REACTIVE` → `isUse()`；导入更新                                                    |
| `props.ts`            | `IS_REACTIVE` → `isUse()`；`effect()` → `use(...)`；导入更新                           |
| `process-children.ts` | `IS_REACTIVE` → `isUse()`；`effect()` → `use(...)`；导入更新                           |
| `directives.ts`       | `IS_REACTIVE` → `isUse()`；`effect()` → `use(...)`；`define()` → `use(init)`；导入更新 |
| `ssr-helpers.ts`      | `IS_REACTIVE` → `isUse()`；导入更新                                                    |
| `local-effect.ts`     | 可能需支持从 derivation getter 提取 stop                                               |

### 关键问题：`h()` 需要获取派生 stop 用于 cleanup

在 v3.4 中：

```ts
const stop = effect(() => {
  /* update DOM */
});
addLocalEffect(node, stop);
```

在 v4.0 中，`use(...)` 返回 `[getter, setter]`，不暴露 `stop`。
但框架内部仍需 stop 来注册 cleanup。

**解决方案**：派生节点的内部状态挂载 `state.stop`，`addLocalEffect` 接收 derivation getter 时从中提取：

```ts
const [derived] = use(signal, () => {
  textNode.textContent = String(signal());
});
addLocalEffect(textNode, derived[REACTIVE].stop);
```

`addLocalEffect` 保持接受 `() => void` 的当前接口不变——调用方自行提取 `stop`。

## 阶段四：移除旧 API + 更新依赖模块

**目标**：清理旧代码，所有模块使用新 API。

### 改动内容

| 文件                 | 改动                                                                                   |
| -------------------- | -------------------------------------------------------------------------------------- |
| `runtime.ts`         | 删除 `define`/`effect`/`derive` 的导出（保留内部实现直到所有引用迁移）                 |
| `types.ts`           | 删除 `STOP_KEY`、`ReactiveFunction`                                                    |
| `components.ts`      | `lazy`：`define` → `use(init)`                                                         |
| `async.ts`（romise） | `define` → `use(init)`，`effect` → `use(...)`                                          |
| `index.ts`           | 导出 `use`/`isUse`/`toUse`/`toVal`，删除 `define`/`effect`/`derive`/`ReactiveFunction` |
| `router/index.ts`    | 如使用旧 API 则迁移                                                                    |
| `server/index.ts`    | 如使用旧 API 则迁移                                                                    |

**最终 `index.ts` 导出清单**：

```ts
// Core
export { use, isUse, toUse, toVal } from "./core/runtime.ts";
// Lifecycle
export { onMount, onUnmount, mount, unmount } from "./core/lifecycle.ts";
// Components
export { Teleport, lazy } from "./core/components.ts";
// Async
export { romise } from "./core/async.ts";
// DOM
export { h } from "./core/h.ts";
// JSX
export { jsx, jsxs, jsxDEV } from "./jsx-runtime/index.ts";
// Types
export type { Getter, Setter } from "./core/types.ts";
```
