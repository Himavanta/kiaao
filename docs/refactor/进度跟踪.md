> 关联文档：[spec.md](./spec.md)（设计规范）、[doc.md](./doc.md)（讨论纪要）
> 目标：将核心响应式系统从 4 API（define/derive/effect/selector）统一为 1 API（use）

## 目录结构设计

本次重构同时重新组织 `src/` 目录，为未来的水合和跨端需求做准备。

```
src/
├── index.ts                    # 公共导出
│
├── reactive/                   # ⭐ 纯响应式系统（零 DOM 依赖，平台无关）
│   ├── types.ts                #    REACTIVE Symbol, Getter, Setter, 内部节点类型
│   └── core.ts                 #    use(), isUse(), toUse(), toVal() 实现
│
├── dom/                        # DOM 平台 + 组件模型
│   ├── component.ts            #    组件栈、生命周期、mount/unmount
│   ├── h.ts                    #    h() 函数
│   ├── directives.ts           #    when / each 指令
│   ├── dom-utils.ts            #    DOM 工具函数（createElement、SVG 检测等）
│   ├── props.ts                #    属性/事件处理
│   ├── process-children.ts     #    子节点处理
│   ├── local-effect.ts         #    LOCAL_EFFECTS 注册与清理
│   ├── teleport.ts             #    Teleport 组件
│   ├── lazy.ts                 #    lazy 异步组件
│   ├── async.ts                #    romise
│   └── ssr-helpers.ts          #    hSSR / SSR 渲染
│
├── server/                     # SSR 公共 API 入口（不变）
├── jsx-runtime/                # 不变
├── jsx-dev-runtime/            # 不变
├── astro/                      # 不变
└── router/                     # 不变
```

### 设计理由

| 关注点                                   | 方案                                                          |
| ---------------------------------------- | ------------------------------------------------------------- |
| **响应式核心** → `reactive/`             | 零 DOM 依赖，任何平台（DOM / 原生 / Canvas）直接复用          |
| **DOM 渲染层** → `dom/`                  | 水合逻辑（`dom/hydrate.ts`）自然收敛于此                      |
| **组件模型** → `dom/component.ts`        | 移出运行时，与平台语义绑定（mount/unmount 本来就是 DOM 操作） |
| `SPEC.md` 专注 API 契约                  | 不耦合平台实现细节                                            |
| `reactive/types.ts` 导出 REACTIVE Symbol | DevTools 和其他平台依赖同一套符号                             |

**迁移对照**（`src/core/` → 新位置）：

| 旧路径                     | 新路径                                                     |
| -------------------------- | ---------------------------------------------------------- |
| `core/runtime.ts`          | `reactive/core.ts`（响应式）+ `dom/component.ts`（组件栈） |
| `core/types.ts`            | `reactive/types.ts`                                        |
| `core/h.ts`                | `dom/h.ts`                                                 |
| `core/directives.ts`       | `dom/directives.ts`                                        |
| `core/dom-utils.ts`        | `dom/dom-utils.ts`                                         |

## 阶段一：`reactive/` 目录 + 辅助函数

**目标**：建立 `reactive/types.ts` 和 `reactive/core.ts` 骨架，`isUse`/`toUse`/`toVal` 可用，`use` 尚不可用。

### 新建文件

#### `src/reactive/types.ts`

- `REACTIVE = Symbol("reactive")` — 指向内部状态对象
- 内部状态类型：
  - `DefinitionState<T>`: `{ value: T; subs: Set<any>; set: Setter<T> }`
  - `DerivationState<T>`: `{ deps; cachedValue; subs; computeFn; set; stops; stop }`
- 公共类型：
  - `Getter<T>` — 简化为 `() => T`（删除选择器重载）
  - `Setter<T>` — 不变
- ❌ 不再导出 `ReactiveFunction`、`STOP_KEY`

#### `src/reactive/core.ts`

- ✅ `isUse(v: any): boolean` — 检查 `v?.[REACTIVE] !== undefined`
- ✅ `toUse<T>(v: T): [Getter<T>, Setter<T>]`
  - `isUse(v)` → 返回 `[v, v[REACTIVE].set]`
  - 否则 → 等价于 `use(v)`（阶段二完成）
- ✅ `toVal(v: any): any` — `isUse(v) ? v() : v`
- ⏳ `use`（留空壳，次阶段完成）
- ✅ `setRenderMode` / `getRenderMode` — 保留，移至此处
  - 虽然渲染模式偏 DOM 概念，但 SSR 场景下派生信号的行为也受其影响，放在 reactive 层

> 所有 DOM 相关上下文（componentStack、currentComponent 等）移至阶段三的 `dom/component.ts`。

### 边界问题

- `isUse`、`toUse`、`toVal` 不依赖任何 DOM API → 可安全放置在 `reactive/`
- 渲染模式（`dom` / `ssr` / `hydrate`）影响派生行为 → 留在 `reactive/`

## 阶段二：`use` 完整实现

**目标**：`reactive/core.ts` 中 `use` 的定义模式和派生模式可用，更新传播正确。

### 改动内容

#### `src/reactive/core.ts` — `use` 函数

**定义模式** `use(initialValue)`：

- 创建 `DefinitionState`
- `getter` 挂载 `[REACTIVE] = state`
- `setter`：`value !== oldValue` → 通知 `subs`
- `state.set = setter`

**派生模式** `use(...deps, computeFn)`：

- 参数解析：`const [func, ...deps] = ars.reverse()`
- 创建 `DerivationState`，遍历 `deps` 将自身注册到各依赖的 `subs`
- 初始执行 `computeFn(undefined)` 建立缓存
- `setter` 逻辑：触发 `computeFn(value)`，短路判断
- 上游变化触发：`computeFn(undefined)` → 短路 → 递归下游
- 返回 `[getter, setter]`，getter 挂载 `[REACTIVE] = state`
- `state.stop` = 统一清理函数（遍历 `stops` 移除所有订阅）
- `state.set = setter`

**类型重载**（TS）：

```ts
function use<T>(initialValue: T): [Getter<T>, Setter<T>];
function use<T>(...deps: [...Signal[], (v?: any) => T]): [Getter<T>, Setter<T>];
function use(...deps: [...Signal[], (v?: any) => void]): [Getter<void>, Setter<void>];
```

**开发模式校验**：

- 最后一个参数不是函数 → 警告并返回
- 最后一个参数是信号 → 警告
- 依赖中存在非信号 → 警告并过滤

### 关键实现细节

| 场景             | computeFn 参数           | 触发条件                 |
| ---------------- | ------------------------ | ------------------------ |
| 创建时初始执行   | `undefined`              | 同步                     |
| 上游依赖变化     | `undefined`              | `setter()` 或上游 setter |
| 派生 setter 调用 | `setter(value)` 传入的值 | `setValue(42)`           |

短路逻辑：`newResult === cachedValue` → 不通知下游。

## 阶段三：`dom/` 目录迁移 + `h()` 链路适配

**目标**：创建 `dom/` 目录，从旧 `core/` 迁移并适配为新信号系统。

### 新建 / 迁移文件

| 新路径                    | 来源                                           | 改动                                                                         |
| ------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------- |
| `dom/component.ts`        | `core/lifecycle.ts` + `core/runtime.ts` 的部分 | 合并生命周期 + 组件栈逻辑，`IS_REACTIVE` → `isUse()`                         |
| `dom/h.ts`                | `core/h.ts`                                    | 导入路径更新                                                                 |
| `dom/props.ts`            | `core/props.ts`                                | `IS_REACTIVE` → `isUse()`，`effect()` → `use(...)`                           |
| `dom/process-children.ts` | `core/process-children.ts`                     | `IS_REACTIVE` → `isUse()`，`effect()` → `use(...)`                           |
| `dom/directives.ts`       | `core/directives.ts`                           | `IS_REACTIVE` → `isUse()`，`effect()` → `use(...)`，`define()` → `use(init)` |
| `dom/dom-utils.ts`        | `core/dom-utils.ts` + `core/escape.ts`         | 合并 escape，其他不变                                                        |
| `dom/local-effect.ts`     | `core/local-effect.ts`                         | 不变（接口保持接受 `() => void`）                                            |
| `dom/teleport.ts`         | `core/components.ts` 中的 Teleport             | 分离为独立文件                                                               |
| `dom/lazy.ts`             | `core/components.ts` 中的 lazy                 | 分离为独立文件                                                               |
| `dom/async.ts`            | `core/async.ts`                                | 导入更新                                                                     |
| `dom/ssr-helpers.ts`      | `core/ssr-helpers.ts`                          | `IS_REACTIVE` → `isUse()`                                                    |

### `h()` 与 `stop` 的配合

```ts
// 在 process-children.ts 中：
const [derived] = use(signal, () => {
  textNode.textContent = String(signal());
});
addLocalEffect(textNode, derived[REACTIVE].stop);
```

`addLocalEffect` 接口不变，调用方从 derivation getter 的 `REACTIVE` 状态中提取 `stop`。
