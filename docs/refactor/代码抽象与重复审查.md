## 发现：影响阅读的重复

### 1. `directives.ts` — child 清理循环重复 3 次（影响最大）

```ts
const removed = createFragment();
let child: Node | null;
while ((child = firstChild(el))) {
  disposeNode(child);
  removed.append(child);
}
```

这段 7 行代码在 `renderBranch` 的**映射表模式**、**布尔 isLazy 模式**、**非惰性模式** 各出现一次（~line 225 / 250 / 270）。作者要表达的意思只有一句"清空当前子节点"，但每次都要读完 7 行才能确认。

**建议方案**：提取为 `clearChildren(el)` 工具函数。

---

### 2. `core.ts` — getter/setter 创建在两种模式下重复

定义模式（~line 105-115）：

```ts
const getter = (() => state.value) as Getter<T>;
(getter as any)[REACTIVE] = state;

const setter = ...;

state.set = setter;
return [getter, setter];
```

派生模式（~line 195-205）：

```ts
const getter = (() => state.cachedValue) as Getter<T>;
(getter as any)[REACTIVE] = state;

const setter = ...;

state.set = setter;
return [getter, setter];
```

**区别只有 `state.value` vs `state.cachedValue` 和 setter 内部逻辑**。但创建 getter、挂标记、赋值 set、返回元组这 6 行完全一样。

**建议方案**：提取 `createSignal(state)` 共享函数，接受一个 `state` 对象并返回 `[getter, setter]`。两种模式的差异只在 setter 行为，可各自传入。

---

### 3. `h.ts` — `context` 对象内联在组件模式路径中

`createContext(instance)` ~25 行（line 52-76）的 `onMount`/`onUnmount` 逻辑内联在 `h()` 的组件分支中。这段逻辑与 `h()` 的核心职责（创建 DOM、调用组件）无关，且让组件路径首次阅读时需要跳过一大段 context 逻辑才能看到后面的 async/sync 分支。

**建议方案**：提到 `component.ts` 中，导出 `createComponentContext(instance)`。

---

### 4. `directives.ts` / `ssr-helpers.ts` — when 的三态检测逻辑镜像

`directives.ts` 中的 `isMappingMode / isLazy / hasEach` 检测和 `ssr-helpers.ts` 中的 when 路由逻辑结构一致，但因为输出不同（DOM vs SSRSafe）无法抽象共享。这个是本质性重复，不处理。
