# Kiaao 控制流组件首次渲染时机优化专题文档

**状态**：最终设计  
**版本**：3.0  
**日期**：2026-06-30

---

## 1. 背景与动机

在重构后的 Kiaao 架构中，`h()` 不再依赖 `nestBind` 二次遍历，所有 DOM 节点构建在 `h()` 内部一次性完成，并通过 `adoptResult` 在组件边界统一建立 Owner 关系。新架构消除了轻量 Owner，纯化了 Owner 语义，使控制流组件的优化成为可能。

当前控制流组件（`Show`、`Case`、`Each`）依赖 `context.onMount` 延迟首次分支渲染。其根本原因是旧架构下 `adoptBranch` 内部调用 `adapter.before(anchor, node)` 将分支内容插入锚点之前，要求锚点必须已存在于 DOM 中。`onMount` 回调在锚点被父级插入 DOM 后执行，保证 `before` 操作有效。

新架构下，`handleDomMode` 在 `h()` 内部完成所有子节点 DOM 插入，`HResult.nodes` 是扁平节点数组，父组件按序 `append`。控制流组件只需确保返回的 `nodes` 数组顺序正确——内容在前、锚点在后——父组件就能自然地将内容插入锚点之前。这使得在函数体内同步完成首次渲染成为可能。

---

## 2. 问题分析

### 2.1 首次渲染与后续更新的冲突

`adoptBranch` 同时用于首次渲染和后续更新，其内部 `adapter.before(anchor, node)` 在首次渲染时锚点尚未插入 DOM，会触发 `NotFoundError`（DOM 平台）。旧架构通过 `onMount` 延迟渲染绕过此问题，但带来了额外的生命周期依赖和 SSR 兼容问题。

### 2.2 SSR 兼容性

SSR 适配器没有 `onMount` 概念，控制流组件目前只输出注释锚点，无法输出实际内容。如果首次渲染能同步完成，SSR 下自然获得正确输出。

### 2.3 自引用问题

控制流组件返回的边界 HResult 若将 `owner` 设为其自身的 Owner（`context.owner`），则 `handleComponent` 在内部调用 `adoptResult(owner, childHr)` 时，会出现 `hr.owner === owner` 的自引用情况，导致 `owner.children` 包含自身，形成循环引用。

---

## 3. 解决方案

### 3.1 为 `adoptBranch` 增加 `skipInsert` 参数

**修改文件**：`core/flow-shared.ts`

```ts
export function adoptBranch(options: {
  parentOwner: Owner;
  anchor: HostNode;
  Component: ComponentFunction;
  componentProps?: any;
  skipInsert?: boolean;
}): HResult {
  const { parentOwner, anchor, Component, componentProps, skipInsert } = options;
  const adapter = getAdapter();

  const props =
    componentProps && isFunction(componentProps.children)
      ? { ...componentProps, children: componentProps.children() }
      : componentProps;

  const r = h(Component, props);
  adoptResult(parentOwner, r);

  if (!skipInsert) {
    for (const node of r.nodes) {
      adapter.before(anchor, node);
    }
    if (r.owner) triggerMount(r.owner);
  }

  return r;
}
```

**关键变化**：

- 新增 `skipInsert?: boolean` 参数，默认 `undefined`（视作 `false`）。
- `skipInsert` 为 `true` 时，跳过 `before` 和 `triggerMount`，仅做渲染和 Owner 挂接。
- `skipInsert` 为 `false` 时，保持原有行为，并触发新子组件的挂载。

### 3.2 控制流组件改造

#### 3.2.1 Show 组件

**修改文件**：`core/show.ts`

```ts
export function Show(props, context): HResult {
  const anchor = adapter.comment("show");
  context.owner.elements.add(anchor);

  const [primary, fallback] = normalizeChildList(props.children);
  let currentResult: HResult | null = null;

  const renderBranch = (isInitial: boolean) => {
    if (currentResult?.owner) disposeOwner(currentResult.owner);
    const value = toValue(props.value);
    const Component = value ? primary : fallback;
    if (Component) {
      currentResult = adoptBranch({
        parentOwner: context.owner,
        anchor,
        Component,
        skipInsert: isInitial,
      });
    } else {
      currentResult = null;
    }
  };

  renderBranch(true); // 首次

  subscribeSignal(context.owner, props.value, () => renderBranch(false));

  const nodes = currentResult ? [...currentResult.nodes, anchor] : [anchor];
  return createHResult(context.owner, nodes, [], []);
}
```

**变化**：

- 移除 `context.onMount(renderBranch)`。
- 首次调用 `renderBranch(true)`，信号回调中调用 `renderBranch(false)`。
- 返回边界 HResult，`owner` 为 `context.owner`。

#### 3.2.2 Case 组件

**修改文件**：`core/case.ts`

与 `Show` 改造模式一致：在函数体内调用 `renderBranch(true)`，信号回调中调用 `renderBranch(false)`，`adoptBranch` 传入相应的 `skipInsert` 值。

#### 3.2.3 Each 组件

**修改文件**：`core/each.ts`

**首次渲染与后续更新分离**：

```ts
export function Each(props, context): HResult {
  const anchor = adapter.comment("each");
  context.owner.elements.add(anchor);

  // ... 初始化 state ...

  const sync = (isInitial: boolean) => {
    const items = isArray(toValue(props.value)) ? toValue(props.value) : [];

    if (isInitial) {
      // 首次：纯构建，无旧条目需要清理
      for (const [i, rawValue] of items.entries()) {
        const identity = props.keyed ? props.keyed(rawValue, i) : i;
        const result = renderEachEntry(state, rawValue, identity, i, true);
        state.entries.push({ key: identity, result });
      }
      return;
    }

    // 后续更新
    if (isEmpty(items)) {
      clearAllEntries(state);
      return;
    }
    if (props.keyed) {
      diffEntries(state, items, props.keyed);
    } else {
      rebuildAllItems(state, items);
    }
  };

  sync(true); // 首次

  subscribeSignal(context.owner, props.value, () => sync(false));

  const allNodes = state.entries.flatMap((e) => e.result.nodes);
  return createHResult(context.owner, [...allNodes, anchor], [], []);
}
```

**`renderEachEntry` 增加 `skipInsert` 参数**：

```ts
function renderEachEntry(
  state: EachState,
  rawValue: any,
  identity: any,
  index: number,
  skipInsert: boolean,
): HResult {
  const itemSignal = definitionMode(rawValue);
  state.itemSignalMap.set(identity, itemSignal);
  return adoptBranch({
    parentOwner: state.owner,
    anchor: state.anchor,
    Component: state.itemComponent,
    componentProps: { item: itemSignal, index },
    skipInsert,
  });
}
```

**注意**：`diffEntries` 和 `rebuildAllItems` 内部调用 `renderEachEntry` 时传入 `false`。

### 3.3 修复 `adoptResult` 自引用

**修改文件**：`core/component.ts`

```ts
export function adoptResult(owner: Owner, hr: HResult): HostNode[] {
  if (hr.owner) {
    // 边界：只挂接外部组件/指令 Owner（排除自身）
    if (hr.owner !== owner && !hr.owner.disposed) {
      owner.children.push(hr.owner);
      hr.owner.parent = owner;
    }
    return hr.nodes;
  }
  // 非边界：吸收所有资源
  for (const node of hr.nodes) {
    owner.elements.add(node);
  }
  for (const childOwner of hr.pending) {
    if (!childOwner.disposed) {
      owner.children.push(childOwner);
      childOwner.parent = owner;
    }
  }
  owner.cleanups.push(...hr.cleanups);
  return hr.nodes;
}
```

**说明**：新增 `hr.owner !== owner` 守卫避免了控制流组件返回自身 Owner 时的自引用。任何组件返回自己的 Owner 作为边界时都会受益，保证 `adoptResult` 通用性。

## 4. 嵌套控制流 anchor 层级验证

内层控制流组件的 `nodes`（内容 + 内层锚点）作为外层 `adoptBranch` 的 `r.nodes`，被 `before(outerAnchor, node)` 逐个插入外层 DOM。最终 DOM 结构：

```
innerContent, innerAnchor, outerAnchor
```

内层后续更新时，`before(innerAnchor, newContent)` 在其局部范围内正确操作，外层锚点不受影响。无需特殊处理。

---

## 5. 信号订阅兼容性

`subscribeSignal` 内部 `initialized` 跳过机制与同步首次渲染兼容：首次渲染手动执行后，信号订阅跳过首次回调；后续信号变化时 `initialized === true`，正常执行更新逻辑。无需修改。

---

## 6. `triggerMount` 路径确认

- **首次渲染**：`skipInsert: true`，`adoptBranch` 不调用 `triggerMount`。子组件 Owner 已挂入控制流 Owner 的 `children`。`createApp.mount` 统一触发 `triggerMount(rootOwner)`，沿 Owner 树到达所有子组件。
- **后续更新**：`skipInsert: false`，`adoptBranch` 手动调用 `triggerMount(r.owner)`，确保新增子组件的 `onMount` 执行。

路径完整，无遗漏。

---

## 7. 对 SSR 的影响

SSR 适配器中 `before` 为空操作，`triggerMount` 无实际效果。`skipInsert` 参数对 SSR 透明。控制流组件在 SSR 下同步执行首次渲染，返回完整节点树，`renderToString` 序列化为正确 HTML。无需模式判断或额外变体。

---

## 8. 与旧方案对比

| 维度         | 旧方案（onMount）           | 新方案（skipInsert）                                  |
| ------------ | --------------------------- | ----------------------------------------------------- |
| 首次渲染触发 | `context.onMount` 异步延迟  | 函数体内同步执行                                      |
| DOM 插入方式 | 依赖锚点已插入，用 `before` | 首次通过返回 nodes 由父级 `append`；后续通过 `before` |
| SSR 兼容     | 需额外处理                  | 自动兼容                                              |
| 代码路径     | 首次与后续分离              | 统一渲染函数，参数控制行为                            |
| 自引用问题   | 无（返回 `owner: null`）    | 已通过 `adoptResult` 守卫修复                         |

## 9. 迁移步骤

1. 修改 `adoptBranch`（`core/flow-shared.ts`）：增加 `skipInsert` 参数，调整插入和挂载逻辑。
2. 改造 `Show`（`core/show.ts`）：移除 `onMount`，同步首次渲染，信号回调执行后续更新。
3. 改造 `Case`（`core/case.ts`）：同 `Show`。
4. 改造 `Each`（`core/each.ts`）：分离首次构建与后续 diff；`renderEachEntry` 增加 `skipInsert` 参数并透传。
5. 修复 `adoptResult`（`core/component.ts`）：边界路径增加 `hr.owner !== owner` 守卫。
6. 清理：移除控制流组件中不再需要的 `onMount` 引用。
7. 测试：客户端首次渲染、后续信号更新、嵌套控制流、SSR 输出、条件切换。

---

## 10. 总结

通过为 `adoptBranch` 增加 `skipInsert` 参数，控制流组件摆脱了对 `onMount` 的依赖，实现首次渲染同步化。`adoptResult` 自引用修复保证了边界 HResult 的安全性。`Each` 首次构建与后续 diff 分离，逻辑清晰。嵌套控制流、信号兼容性、挂载路径均已验证。该方案对 SSR 透明，改动最小，语义清晰，是当前架构下的最优解。
