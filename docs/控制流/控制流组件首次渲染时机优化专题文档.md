# Kiaao 控制流组件首次渲染时机优化专题文档

**状态**：设计定稿  
**版本**：1.0  
**日期**：2026-06-30

---

## 1. 背景与动机

在重构后的 Kiaao 架构中，`h()` 不再依赖 `nestBind` 二次遍历，所有 DOM 节点构建在 `h()` 内部一次性完成。这为控制流组件（`Show`、`Case`、`Each`）的优化提供了新的可能。

当前控制流组件依赖 `context.onMount` 来延迟首次分支渲染。原因在于，旧架构下 `adoptBranch` 内部调用 `adapter.before(anchor, node)` 将分支内容插入锚点之前，这要求锚点必须已存在于 DOM 中。`onMount` 回调在锚点被父级插入 DOM 后执行，保证了 `before` 操作的有效性。

然而，在新架构下，控制流组件完全可以在函数体内同步完成首次渲染，不再需要等待挂载事件。这不仅简化了逻辑，还使得控制流组件在 SSR（无 `onMount`）下自动获得正确输出。

## 2. 问题分析

控制流组件首次渲染时，锚点尚未被父级插入 DOM。如果此时调用 `adapter.before(anchor, node)`，DOM 平台会抛出 `NotFoundError`。而 `onMount` 通过延迟渲染规避了这个问题。

但新架构下，`h()` 返回的 `HResult.nodes` 是扁平节点数组，父组件会按顺序将这些节点 `append` 到容器中。控制流组件只需确保返回的 `nodes` 数组顺序正确——内容节点在前，锚点在后——父组件就会自然地将内容插入到锚点之前。后续信号变化时，锚点已在 DOM 中，`before` 操作可以安全执行。

核心矛盾：**同一个 `adoptBranch` 既用于首次渲染（需要跳过 DOM 插入），又用于后续更新（需要执行 DOM 插入）。**

## 3. 解决方案

为 `adoptBranch` 增加 `skipInsert?: boolean` 参数。首次渲染时传递 `skipInsert: true`，跳过 `before` 调用；后续更新时传递 `skipInsert: false` 或省略（默认行为），执行 DOM 插入。

同时，移除 `adoptBranch` 中针对首次渲染多余的 `triggerMount` 调用，仅在后续更新中触发新子组件的挂载。

### 3.1 `adoptBranch` 修改

```ts
export function adoptBranch(options: {
  parentOwner: Owner;
  anchor: HostNode;
  Component: ComponentFunction;
  componentProps?: any;
  skipInsert?: boolean; // 新增：首次渲染时跳过 DOM 插入
}): HResult {
  const { parentOwner, anchor, Component, componentProps, skipInsert } = options;
  const adapter = getAdapter();

  // children 为函数时调用以获取新内容（跨控制流开关重建）
  const props =
    componentProps && isFunction(componentProps.children)
      ? { ...componentProps, children: componentProps.children() }
      : componentProps;

  const r = h(Component, props);
  adoptResult(parentOwner, r);

  if (!skipInsert) {
    // 后续更新：直接插入 DOM
    for (const node of r.nodes) {
      adapter.before(anchor, node);
    }
    // 后续更新中如果创建了新子组件，需要手动触发其挂载
    if (r.owner) triggerMount(r.owner);
  }
  // 首次渲染：跳过插入，节点由父组件通过返回的 nodes 统一插入

  return r;
}
```

### 3.2 `Show` 组件改造

```ts
export function Show(props, context): HResult {
  const anchor = adapter.comment("show");
  context.owner.elements.add(anchor);

  const [primary, fallback] = normalizeChildList(props.children);
  let currentResult: HResult | null = null;

  const renderBranch = (isInitial: boolean) => {
    if (currentResult?.owner) disposeOwner(currentResult.owner);
    const value = toValue(props.value);
    const Component = value ? primary : fallback;
    if (Component) {
      currentResult = adoptBranch({
        parentOwner: context.owner,
        anchor,
        Component,
        skipInsert: isInitial,
      });
    } else {
      currentResult = null;
    }
  };

  // 首次渲染：skipInsert = true，节点通过返回的 nodes 插入
  renderBranch(true);

  // 后续更新：skipInsert = false，直接操作 DOM
  subscribeSignal(context.owner, props.value, () => renderBranch(false));

  const nodes = currentResult ? [...currentResult.nodes, anchor] : [anchor];
  return createHResult(context.owner, nodes, [], []);
}
```

### 3.3 `Case` 组件改造

与 `Show` 类似，首次渲染时传 `skipInsert: true`。

### 3.4 `Each` 组件改造

`Each` 的首次渲染需要为每个条目调用 `renderEachEntry`，该函数内部使用 `adoptBranch`。只需在首次渲染循环中传入 `skipInsert: true`，并将所有条目节点收集起来与锚点一起返回。

```ts
// 在 renderEachEntry 中增加 skipInsert 参数
function renderEachEntry(
  state: EachState,
  rawValue: any,
  identity: any,
  index: number,
  skipInsert: boolean,
): HResult {
  const itemSignal = definitionMode(rawValue);
  state.itemSignalMap.set(identity, itemSignal);
  return adoptBranch({
    parentOwner: state.owner,
    anchor: state.anchor,
    Component: state.itemComponent,
    componentProps: { item: itemSignal, index },
    skipInsert,
  });
}
```

首次渲染时：

```ts
// 在 Each 函数体中
renderAll(true); // 内部调用 renderEachEntry 时传 skipInsert: true
const allNodes = state.entries.flatMap((e) => e.result.nodes);
return createHResult(context.owner, [...allNodes, anchor], [], []);
```

后续更新时，`sync(false)` 内部继续使用 `skipInsert: false`（默认），执行 DOM 插入和 diff 移动。

## 4. 对 SSR 的影响

SSR 适配器中 `before` 为空操作，因此 `skipInsert` 参数在 SSR 下天然透明。控制流组件在 SSR 中同步执行，首次渲染返回完整节点树，`renderToString` 递归序列化即可输出正确 HTML。

无需为 SSR 编写任何特殊逻辑或 `SSR_COMPONENT` 变体。

## 5. 与旧方案对比

| 维度               | 旧方案（onMount）                  | 新方案（skipInsert）                                |
| ------------------ | ---------------------------------- | --------------------------------------------------- |
| 首次渲染触发       | `context.onMount` 异步延迟         | 函数体内同步执行                                    |
| DOM 插入时机       | 锚点已插入后，通过 `before`        | 首次通过返回 nodes 由父级 append；后续通过 `before` |
| SSR 支持           | 需额外处理（SSR 无 onMount）       | 自动兼容                                            |
| 代码路径           | 首次与后续分离（onMount + signal） | 统一渲染函数，通过参数控制行为                      |
| 依赖 `adoptBranch` | 使用 `before`，必须等待挂载        | 首次跳过 `before`，可同步调用                       |
| 复杂度             | 需理解 onMount 时机                | 直观的同步渲染                                      |

## 6. 注意事项

1. **`triggerMount` 的调用时机**：首次渲染时，子组件的 `onMount` 由父组件的 `triggerMount` 统一触发（在 `createApp.mount` 或父组件渲染完成后）。后续更新中，如果创建了新子组件，`adoptBranch` 内部需手动调用 `triggerMount(r.owner)`，确保其 `onMount` 执行。

2. **`Each` 的 diff 逻辑**：现有 `diffEntries` 中使用了 `repositionEntry` 进行节点移动，这些操作基于 `adapter.before`，在首次渲染时不应调用。首次渲染时直接构建节点数组即可。

3. **边界 HResult**：控制流组件返回的 HResult 应将 `owner` 设为 `context.owner`（组件自身的 Owner）。这让 `handleComponent` 的 `adoptResult` 走边界路径，避免重复注册节点。

4. **锚点的归属**：锚点注释节点通过 `context.owner.elements.add(anchor)` 注册到控制流组件自己的 Owner。当控制流组件被销毁时，锚点随组件一起移除。

5. **信号订阅**：`subscribeSignal` 内部的 `initialized` 跳过机制保持不变，因为首次渲染已手动执行。

## 7. 迁移步骤

1. **修改 `adoptBranch`**：增加 `skipInsert` 参数，调整插入和挂载逻辑。
2. **改造 `Show`**：移除 `onMount`，在函数体内调用 `renderBranch(true)`，信号回调中调用 `renderBranch(false)`。
3. **改造 `Case`**：同 `Show`。
4. **改造 `Each`**：在首次渲染路径中传递 `skipInsert: true`，手动收集节点并返回。
5. **清理**：移除控制流组件中不再需要的 `onMount` 引用，移除 `flow-shared.ts` 中无用的 `triggerMount` 调用（保留在 `adoptBranch` 后续更新分支中）。
6. **测试**：验证客户端首次渲染、后续信号更新、SSR 输出、条件切换时的 DOM 变化与生命周期回调。

## 8. 结语

通过给 `adoptBranch` 增加一个简单的 `skipInsert` 参数，控制流组件彻底摆脱了对 `onMount` 的依赖，实现了首次渲染的同步化。这既简化了内部逻辑，又使得 SSR 支持天然无缝。该方案改动最小、语义清晰，是当前架构下的最优解。
