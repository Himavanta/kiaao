# kiaao 开发记录

## 项目概况

**kiaao**：超轻量级、零编译、无虚拟 DOM 的响应式前端框架。

- 核心概念：4 个（define / derive / effect / h）
- 总 API：10 个（Teleport / lazy / onMount / onUnmount / mount / unmount + 4 核心）
- 控制流：通过 `h()` 的原生属性指令 `when`/`each` 实现
- 设计哲学：显式选择器订阅，纯运行时细粒度更新
- 代码量目标：约 385-445 行

### 关键实现决策

- **Getter 设计**：`getter(selector)` 返回 `() => R` 响应式函数（非立即求值），挂载 `IS_REACTIVE` Symbol
- **依赖追踪**：信号内部 `Map<selectorFn, Set<DepEntry>>`，effect 维护 `ownedDeps` 双向引用（Vue 3 范式）
- **清理机制**：effect 重跑前清理旧 dep、重跑中重新收集；stop 函数从所有信号中移除条目
- **derive**：内部用 `define` 做版本信号，内部 `effect` 监听上游，值不变时跳过版本 bump
- **notifySignal 安全**：快照 deps 后再迭代，避免 effect 重跑时修改 Map 导致死循环
- **组件生命周期**：`h(component)` 创建实例压栈，`onMount/onUnmount` 注册到栈顶实例，`mount/unmount` 递归遍历 DOM 树触发

### 2026-06-07 Phase 5 — when/each 指令重构

- **架构变更：控制流从「组件」下沉到「原生元素属性」**
  - `Show`/`List` 组件移除，不再作为公共 API 导出
  - `h()` DOM 模式新增 `when`、`each`、`key` 保留属性识别
  - `Fragment` 废弃，`jsx-runtime` 移除 Fragment 导出
  - 控制流通过 `when`/`each` 属性指令直接依附于原生 DOM 元素

- **`h()` 新增内部函数**
  - `createWhenElement`：条件渲染宿主元素，支持惰性求值函数 `() => any` 和静态子节点
  - `createEachElement`：列表渲染宿主元素，渲染函数接收 `(item, index)`
  - `when` + `each` 共存时 `when` 优先
  - void 元素（`<br>`、`<input>` 等）使用 `when`/`each` 时抛出错误
  - 内部创建 component instance + 通过 `addLocalEffect` 注册 effect stop

- **`lazy` 组件更新**
  - 内部使用 `when` 指令（`<div when={Component() !== null} style="display:contents">`）替代 `Show`
  - 不再需要 SSR_COMPONENT 变体

- **`Teleport` 保持组件形式**
  - 唯一保留的控制流组件，因为其行为本质不同（内容移到另一个 DOM 位置）
  - 保留 SSR_COMPONENT 变体

- **生命周期清理机制不变但更简洁**
  - `disposeNode` 递归 `childNodes` 即可抵达所有动态内容
  - 不需要向 fragment 子节点传播 DISPOSE_KEY
  - 不需要 `onUnmount(removeBranch)` 补偿

### 2026-06-07 Phase 5.1 — 代码审查后优化

- **抽取 `setProps` 工具函数**（`src/dom.ts`）
  - 将 createWhenElement、createEachElement、普通元素路径三处重复的 EVENT_RE / IS_REACTIVE / 静态三段属性设置逻辑合并为统一函数
  - 减少约 25 行重复代码，一处修改属性处理逻辑三处受益

- **移除指令内部的 INSTANCE_KEY/DISPOSE_KEY**（`src/dom.ts`）
  - 深度推演六大场景（顶层挂载、组件返回、嵌套指令、子节点生命周期、triggerMount 遍历、effect 清理路径）
  - 核心发现：指令创建的所有 effect 都通过 `addLocalEffect` 注册到 `LOCAL_EFFECTS`，`instance.effectStops` 始终为空
  - 指令的 `instance` 在任何路径下都不执行有效操作，存在与否不影响功能正确性
  - 移除后代码更干净：不创建空实例、不挂无用元数据、不被外层组件模式覆盖时产生困惑

- **`setComponent`/`setError` 简化**（`src/components.ts`）
  - `setError(err)` 可简化：Error 实例不是函数类型，不会被 setter 误判为 updater
  - `setComponent(fn)` 不能简化：组件函数本身就是函数类型，会被 setter 的 `typeof updater === "function"` 判断误认为 updater 模式，必须保留 `() =>` 包装。这是 `define` setter 设计本身的固有歧义
