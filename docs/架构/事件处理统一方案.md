# 事件处理统一方案

> 日期：2026-06-24
> 问题：`EVENT_RE` 在 core/props.ts、dom/props.ts、server/adapter.ts 三处重复处理

---

## 现状

事件处理散布在三处：

| 位置                | 代码                                              | 职责                                  |
| ------------------- | ------------------------------------------------- | ------------------------------------- |
| `core/props.ts`     | `EVENT_RE.test(key)` → `adapter.addEventListener` | 属性迭代时发现事件 → 直接调 adapter   |
| `dom/props.ts`      | `EVENT_RE.test(key)` → `adapter.addEventListener` | 单属性设置时发现事件 → 直接调 adapter |
| `server/adapter.ts` | `startsWith("on")` → `return`                     | SSR 时跳过事件绑定                    |

`core/props.ts` 中 `EVENT_RE` 在 `isUse` 之前检查，导致 `onClick={signal}` 不会走响应式路径（但事件本身就不需要响应式，这是正确的）。

## 分析

### 事件是否需要响应式？

不需要。`onClick={fn}` 是一次性绑定的函数，运行时不会变更。即使有人写 `onClick={signal}`，signal 函数本身作为 handler 直接绑定，行为正确。

### 事件处理是谁的职责？

事件绑定是平台行为：

- DOM 平台 → `el.addEventListener(type, handler)`
- SSR 平台 → 跳过（不存在事件）
- Lynx 平台 → 可能不同的事件模型

core 层不应该知道事件的存在。统一走 `adapter.setProp(el, key, value)` 即可。

### `addEventListener`/`removeEventListener` 是否需要留在接口上？

改后没有外部代码直接调用 `adapter.addEventListener()`。但保留在 `RenderAdapter` 接口上有两个理由：

1. **Hydrate adapter 可能需要**——水合时需要直接绑事件到已存在的 DOM 节点，不经过 `setProp`
2. **接口完整性**——`addEventListener` 是平台渲染能力的一部分，与 `createElement` / `append` 同级

---

## 方案

**`core/props.ts`**：移除 `EVENT_RE` 和事件分支。统一 `adapter.setProp`。

```ts
export function setProps(el, props, cleanups?) {
  if (!isRecord(props)) return;
  for (const key of Object.keys(props)) {
    if (key === "children") continue;
    const value = props![key];
    if (isUse(value)) {
      use(value, () => adapter.setProp(el, key, value()));
    } else {
      adapter.setProp(el, key, value);
    }
  }
}
```

**`dom/adapter.ts`** `setProp`：增加 `EVENT_RE` 检测，事件走 `addEventListener`。

```ts
setProp(el, key, value) {
  if (EVENT_RE.test(key)) {
    el.addEventListener(key.slice(2).toLowerCase(), value);
    return;
  }
  // style / SVG / setAttribute / property ...
}
```

**`dom/props.ts`** `setProp`：简化为纯透传，不再检查事件。

```ts
export function setProp(el, rawKey, value) {
  if (isNil(value)) return;
  getAdapter().setProp(el, rawKey, value);
}
```

**`server/adapter.ts`**：不变，`on*` 前缀的跳过逻辑已经在其 `setProp` 中。

---

## 收益

- core 不再关心事件（职责清晰）
- 事件处理从 3 处变为 1 处（`dom/adapter.ts`）
- 消除了 `EVENT_RE` 在 core 和 dom 的重复定义
