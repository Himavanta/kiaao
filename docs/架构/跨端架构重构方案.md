# 跨端架构重构方案

> 日期：2026-06-24
> 目标：消除 DOM 类型对 core 层的污染，为 SSR、水合、Lynx 等平台提供清晰的接入架构

---

## 目录结构

```
src/
  adapter/          → 全局 _adapter 管理
    index.ts          setAdapter() / getAdapter() / removeNode()
                      （不含任何平台代码，纯基础设施）

  core/             → 框架核心（零平台依赖）
    index.ts          导出所有内容，供各 platform 组装
    types.ts          HResult / HostNode / Owner / Signal / RenderAdapter 等
    signal.ts         信号系统
    h.ts              h() 工厂
    component.ts      组件模型
    owner.ts          Owner 树生命周期
    directives.ts     when / each 指令
    process-children.ts  子节点处理
    direct.ts         指令系统
    props.ts          属性设置通用逻辑（迭代 + 响应式，adapter.setProp 负责平台差异）
    type-guards.ts    通用运行时检查

  dom/              → DOM 平台适配
    index.ts          DOM 模块入口，export * 供 src/index.ts 使用
    adapter.ts        RenderAdapter 的 DOM 实现
    type-guards.ts    DOM 专用检查（isNode / isElement / isSVGElement）

  server/           → SSR 平台适配
    adapter.ts        RenderAdapter 的 SSR 实现（SSRNode 节点树）
    index.ts          renderToString 等公开 API

  hydrate/          → 水合适配（未来）
    adapter.ts        SSR + DOM 混合 adapter
    index.ts          hydrateRoot 等公开 API

  lynx/             → Lynx 平台适配（未来）
    adapter.ts
    index.ts

  index.ts          → 包主入口：core + adapter/ + dom/
                      用户 import { h } from "kiaao"
```

## 核心类型关系

### `HostNode` —— 抽象的宿主节点类型

```ts
// core/types.ts
export type HostNode = unknown;

export interface HResult {
  nodes: HostNode[];
  owner: Owner | null;
  cleanups?: CleanupFn[];
}
```

### `HostNode = unknown` 在 core 层的类型影响

追查所有 `el` / `node` 类型使用位置：

| 位置                                | 当前用法                           | 改为 HostNode 后的处理                                 |
| ----------------------------------- | ---------------------------------- | ------------------------------------------------------ |
| `h.ts` handleDomMode                | `const el: any`                    | ✅ `adapter.createElement()` 返回 `HostNode`，类型兼容 |
| `h.ts` handleDirectiveMode          | `allNodes: Node[]`                 | ✅ 只 push，不操作属性 → `HostNode[]`                  |
| `directives.ts` appendNodes         | `el.append(node)`                  | ❌ 改为 `adapter.append(el, node)`                     |
| `directives.ts` createItemDOMNodes  | `anchor.before(n)`                 | ❌ 改为 `adapter.before(anchor, n)`                    |
| `directives.ts` repositionItemGroup | `.firstChild` / `.previousSibling` | ✅ 改为无位置判断的 `adapter.before()`                 |
| `directives.ts` clearElement        | `.firstChild` / `.removeChild`     | ✅ 去掉（disposeOwner 已覆盖，冗余循环）               |
| `directives.ts` 各函数参数          | `el: Element`                      | ✅ → `el: HostNode`                                    |
| `component.ts` mergeResults         | `allNodes: Node[]`                 | ✅ → `HostNode[]`                                      |
| `process-children.ts`               | `nodes: Node[]`                    | ✅ → `HostNode[]`                                      |
| `create-app.ts` mount               | `for (const node of nodes)`        | ✅ `adapter.append(container, node)` 接受 `HostNode`   |

**结论：** 没有类型无法表达的地方。所有 DOM 特有操作已被或可被 adapter 封装。

```ts
// src/index.ts（DOM 入口）
import { h as coreH } from "./core/h.ts";
import { domAdapter } from "./dom/adapter.ts";

setAdapter(domAdapter);

// 包装 h()，返回的 HResult.nodes 在运行时是 Node[]
export function h(tag: any, props?: any, ...children: any[]): HResult {
  return coreH(tag, props, ...children);
}
```

用户代码中 `h("div").nodes` 类型为 `HostNode[]`（`unknown[]`），但运行时是 `Node[]`。如果需要类型安全，DOM 入口可提供类型断言包装器。

**这与 React 的做法一致：** `ReactElement` 不引用 DOM 类型，`react-dom` 在 render 时处理具体节点。

### `RenderAdapter` 接口

```ts
// core/types.ts
export interface RenderAdapter {
  createElement(tag: string): HostNode;
  createTextNode(text: string): HostNode;
  createComment(text: string): HostNode;
  before(ref: HostNode, child: HostNode): void;
  append(parent: HostNode, child: HostNode): void;
  remove(node: HostNode): void;
  replaceWith(oldNode: HostNode, ...newNodes: HostNode[]): void;
  setProp(el: HostNode, key: string, value: unknown): void;
  addEventListener(el: HostNode, type: string, handler: (...args: any[]) => void): void;
  removeEventListener(el: HostNode, type: string, handler: (...args: any[]) => void): void;
  /** 判断值是否为宿主节点 */
  isNode(value: unknown): value is HostNode;
}
```

### `adapter/` —— 全局 adapter 设置

```ts
// adapter/index.ts
let _adapter: RenderAdapter | null = null;

export function setAdapter(adapter: RenderAdapter): void {
  _adapter = adapter;
}
export function getAdapter(): RenderAdapter {
  /* 抛错或返回 */
}
export function removeNode(node: HostNode): void {
  _adapter?.remove(node);
}
```

**不含任何平台代码。** 只提供读写接口。

### `RenderMode` —— 渲染模式（也从 core 移出）

当前 `RenderMode` 类型和 `setRenderMode` / `getRenderMode` 在 `src/core/signal.ts` 中，core 层通过 `if (currentRenderMode === "ssr")` 判断平台行为。

**问题：** core 层不应该知道自己在什么平台下运行。渲染模式是平台概念，不是信号系统概念。

**方案：** 将 `RenderMode`、`setRenderMode`、`getRenderMode` 从 `signal.ts` 移到 `adapter/index.ts`。

```ts
// adapter/index.ts
export type RenderMode = "dom" | "ssr" | "hydrate";
let _renderMode: RenderMode = "dom";
export const setRenderMode = (mode: RenderMode): void => {
  _renderMode = mode;
};
export const getRenderMode = (): RenderMode => _renderMode;
```

`signal.ts` 中的 SSR 优化路径：

```ts
// currentRenderMode === "ssr" 时的静态求值路径
if (currentRenderMode === "ssr") {
  const value = func(undefined);
  return definitionMode(value);
}
```

**方案：** 移到 `RenderAdapter` 的可选方法 `createStaticDerived` 上，避免 core 感知平台。

```ts
// core/types.ts — RenderAdapter 接口
createStaticDerived?: <T>(fn: (...args: any[]) => T, deps: Signal<any>[]) => Signal<T>;
```

`signal.ts` 中调用：

```ts
function derivationMode<T>(...args: any[]): Signal<T> {
  // ...
  const adapter = getAdapter();
  if (adapter.createStaticDerived) {
    return adapter.createStaticDerived(func, validDeps);
  }
  // 默认完整派生路径...
}
```

SSR adapter 实现：

```ts
export const ssrAdapter: RenderAdapter = {
  createStaticDerived(fn, _deps) {
    const value = fn(undefined);
    return definitionMode(value);
  },
  // ...
};
```

DOM adapter 不实现 `createStaticDerived`，core 走默认路径。

**移出原因：** `RenderMode` / `setRenderMode` / `getRenderMode` 也从 `signal.ts` 移出，放到 `adapter/index.ts` 中（与 `_adapter` 平级的全局配置）。`RenderMode` 类型和读写函数由各 platform entry 使用，core 不再引用。

### 问题

DOM 平台当前有 `dom/props.ts` 中的 `setProps()`，它：

1. 遍历 props 键值
2. 处理信号的响应式绑定
3. 调用 `adapter.setProp(el, key, value)` 完成平台设值

### 分析

步骤 1 和 2 是通用逻辑，步骤 3 是平台差异。`setProps` 应该放在哪？

**放在 dom 层：** core 的 `h()` 不能调用它 → 需要平台 `h()` 包装器额外处理

**放在 core 层：** iterator + reactive 是通用逻辑，`adapter.setProp` 负责平台差异

### 结论

`setProps` 放在 **core 层**。理由是：

```ts
// core/props.ts
export function setProps(el: HostNode, props: NullableProps, cleanups?: CleanupFn[]) {
  if (!isRecord(props)) return;
  for (const key of Object.keys(props)) {
    if (key === "children") continue;
    const value = props[key];
    if (isUse(value)) {
      const derived = use(value, () => adapter.setProp(el, key, value()));
      const stop = getSignalState(derived)?.stop;
      if (stop && cleanups) cleanups.push(stop);
    } else {
      adapter.setProp(el, key, value);
    }
  }
}
```

- `isRecord` / `isUse` / `use` / `getSignalState` 全部是 core 层的工具
- `adapter.setProp` 是平台差异的唯一接触点
- `handleDomMode` 中的 `h("div", { class: "foo" })` 调用 `setProps(el, props)`，无需平台包装器

这样 `dom/props.ts` 不再需要——全部合并到 `core/props.ts`。

## 各平台 adapter

### DOM adapter

```ts
// dom/adapter.ts
export const domAdapter: RenderAdapter = {
  createElement(tag) {
    if (SVG_TAGS.has(tag)) return document.createElementNS(SVG_NS, tag);
    return document.createElement(tag);
  },
  isNode(value) {
    return value instanceof Node;
  },
  addEventListener(el, type, handler) {
    (el as EventTarget).addEventListener(type, handler as EventListener);
  },
  // ...
};
```

### SSR adapter

```ts
// server/adapter.ts
export const ssrAdapter: RenderAdapter = {
  createElement(tag) {
    return { type: "element", tag, attrs: {}, children: [] };
  },
  isNode(value) {
    return typeof value === "object" && value !== null && "type" in value;
  },
  addEventListener() {
    /* SSR 不绑事件 */
  },
  // ...
};
```

### Hydrate adapter（未来）

```ts
// hydrate/adapter.ts
export const hydrateAdapter: RenderAdapter = {
  createElement: ssrAdapter.createElement, // 不创建真实 DOM
  append() {
    /* DOM 结构已存在 */
  },
  addEventListener(el, type, handler) {
    // 水合需要真实绑定事件
    (el as EventTarget).addEventListener(type, handler as EventListener);
  },
  setProp(el, key, value) {
    // 设值直接操作真实 DOM
    (el as Element).setAttribute(key, String(value));
  },
};
```

Hydrate 是 SSR + DOM 的混合体——`createElement`/`append` 走 SSR 路径，`addEventListener`/`setProp` 走 DOM 路径。

## 现有代码的兼容性

架构拆分后：

- `getAdapter()` 仍可用（从 `adapter/index.ts`）
- `HostNode` 是 `unknown`，但 `h()` 返回的 `HResult.nodes` 在运行时不受影响
- `processChildren` 用 `adapter.isNode()` 替代 `isNode()`
- `setProps` 移到 `core/props.ts`，`dom/props.ts` 删除

## 迁移步骤

```
Phase 0: 准备
  ┣ 创建 adapter/ 目录
  ┃  ┣ 从 core/types.ts 剥离 setAdapter/getAdapter/removeNode → adapter/index.ts
  ┃  ┣ 从 core/signal.ts 剥离 RenderMode/setRenderMode/getRenderMode → adapter/index.ts
  ┃  ┗ 不含任何平台代码
  ┣ core/types.ts：type HostNode = unknown，HResult.nodes: Node[] → HostNode[]
  ┣ RenderAdapter：增加 isNode 方法，HostNode 替换 Node/Element
  ┣ core/props.ts：创建新文件（从 dom/props.ts 移动通用逻辑）
  ┣ type-guards.ts 拆分（core/ 通用，dom/ 平台专用）
  ┗ signal.ts：移除 SSR 优化路径（if currentRenderMode === "ssr"）
  ┗ HResult.nodes: Node[] → HostNode[]

Phase 1: 消除 core 对 dom 的依赖
  ┣ core/ 中所有 Node/Element 引用 → HostNode（涉及 h.ts / directives.ts / component.ts / process-children.ts / create-app.ts）
  ┣ directives.ts：el.append → adapter.append；anchor.before → adapter.before
  ┣ directives.ts：去掉 clearElement（冗余，disposeOwner 已覆盖）
  ┣ directives.ts：简化 repositionItemGroup（去掉 .firstChild / .previousSibling 位置判断）
  ┣ process-children.ts：adapter.isNode() 代替 isNode() 和 SSR "type" in child
  ┣ h.ts：handleDomMode el 类型 HostNode
  ┣ 删除 dom/props.ts（逻辑已移至 core/props.ts）
  ┗ 验证：core/ 无 import "../dom/" 的引用

Phase 2: 入口整合
  ┣ src/index.ts → 组合 core + dom adapter
  ┣ server/index.ts → 组合 core + ssr adapter
  ┗ 测试通过

Phase 3: Hydrate / Lynx（未来）
```
