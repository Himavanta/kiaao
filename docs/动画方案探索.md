# 动画方案探索与 Motion 指令实现 v4.0

**状态**：阶段总结 + 实现指南  
**关联**：kiaao v4.2 自定义指令系统  
**日期**：2026年6月15日

> **声明**：本文档中的代码示例均为示意伪代码，用于说明概念和设计模式。代码块中的实现不完整，缺少边界处理、类型标注和错误兜底。具体实现由开发者根据实际需求自行决定。

## 一、背景

### 1.1 问题的起点

kiaao 需要提供声明式的 **进入动画** 和 **退出动画**。进入动画容易实现，但退出动画的难点在于：必须在 DOM 移除**之前**播放动画，而 kiaao 的 DOM 清理（`when`/`each` 的更新）发生在同步的派生回调中。框架核心无法在清理过程中异步等待动画完成。

### 1.2 核心矛盾：异步挂载可行，异步卸载不可行

|            | 异步挂载                 | 异步卸载             |
| ---------- | ------------------------ | -------------------- |
| 触发方     | Promise.then（框架外部） | 派生回调（框架内部） |
| 能否 await | 能（不受同步限制）       | 不能（破坏同步模型） |
| 框架支持   | ✅ 异步组件              | ❌ 不可行            |

**根本原因**：派生回调是同步的，无法阻塞等待动画结束。任何试图在 `disposeNode` 中等待 Promise 的方案都会破坏 kiaao 的响应式核心。

### 1.3 业务状态与动画状态的冲突

早期方案中，用户调用 `play(false)` 触发退出动画并延迟更新信号。这导致所有依赖该信号的 UI（如状态文案）都必须等动画完成才能变化，体验不佳。

**最终思路**：**业务信号与动画信号分离**。用户直接操作业务信号（`state`），业务 UI 立刻响应。`createMotion` 内部通过派生延迟更新动画信号（`visible`），`when` 绑定动画信号。退出动画在延迟期间播放。

## 二、React / Vue / Solid 的退出动画处理方式

（简略）Vue 依赖虚拟 DOM，React 依赖社区方案，Solid 利用信号延迟更新。kiaao 选择 Solid 的模式：**通过派生信号延迟触发移除，在应用层解决动画时序**。

## 三、方案探索与最终方向

最终方向：**工厂函数模式**，指令收集动画任务，派生延迟管理动画信号。根据场景分离两个 API：

- **`createMotion(signal, context?)`**：处理 `when`（布尔值）
- **`createGroupMotion(signal, keyFn?, context?)`**：处理 `each`（数组）

## 四、`createMotion` — when 模式

### 4.1 API 设计

```ts
function createMotion(signal, context?): [visible, Motion];
```

- `signal`：业务信号的 getter（布尔值）
- `context`（可选）：若传入，则用 `context.use` 创建组件级信号，自动清理
- 返回：
  - `visible`：动画信号（派生自 `signal`，延迟更新），绑定到 `when`
  - `Motion`：指令组件，包裹动画元素

### 4.2 实现骨架（伪代码）

```ts
function createMotion(signal, context?) {
  const [getter, setter] = context ? context.use(signal) : use(signal);
  const elements = new Set<Element>();
  const propsMap = new Map<Element, { from: any; to: any; duration: number }>();
  let tick = 0;

  // 动画信号：初始值与业务信号相同
  const [visible, setVisible] = context ? context.use(signal()) : use(signal());

  // 派生：业务信号变化时，延迟更新动画信号
  const derived = context ? context.use : use;
  derived(signal, () => {
    const newValue = signal();
    const myTick = ++tick;
    // 实时计算最大 duration，避免 Set 去重问题
    const delay = Math.max(0, ...[...propsMap.values()].map((p) => p.duration)) * 1000;
    setTimeout(() => {
      if (myTick !== tick) return; // 中途反转，跳过
      setVisible(newValue);
    }, delay);
  });

  // Motion 指令
  const Motion = direct((el, props, ctx) => {
    const { from, to, duration = 0.3 } = props;
    propsMap.set(el, { from, to, duration });

    // 每次重挂载时触发
    ctx.onMount(() => {
      elements.add(el);
      // 进入动画
      if (to) {
        setMotionState(el, "entering");
        void animate(el, to, { duration }).finished.then(() => {
          setMotionState(el, "idle");
        });
      }
      // 注册退出动画监听派生（每次重挂载重新注册）
      ctx.use(signal, () => {
        const currentValue = signal();
        // 守卫：必须提供 from 且当前为退出
        if (!from || typeof currentValue !== "boolean" || !currentValue) return;
        if (getMotionState(el) === "exiting") return;
        setMotionState(el, "exiting");
        void animate(el, from, { duration }).finished.then(() => {
          setMotionState(el, "exited");
        });
      });
    });

    ctx.onUnmount(() => {
      elements.delete(el);
      propsMap.delete(el);
    });
  });

  return [visible, Motion];
}
```

### 4.3 使用示例

```jsx
function Comp(_, context) {
  const [state] = use(true);
  const [visible, Motion] = createMotion(state, context);

  return (
    <div>
      <button onClick={() => state(false)}>关闭</button>
      <span>当前状态：{state ? "开" : "关"}</span> {/* 立刻变化 */}
      <div when={visible}>
        {" "}
        {/* 绑定动画信号 */}
        <Motion from={{ opacity: 0 }} to={{ opacity: 1 }}>
          <div class="content">动画内容</div>
        </Motion>
      </div>
    </div>
  );
}
```

**流程**：`state(false)` → 业务 UI 立刻变化；派生延迟启动；Motion 内部 `ctx.use(signal)` 检测到退出，播放动画；延迟到期 → `visible` 变 false → `when` 移除 DOM。

### 4.4 中途反转

代际标记 (`tick`) 保证：如果在延迟期间 `state` 又变回 `true`，旧定时器被跳过，`visible` 保持 `true`，元素不退出。

## 五、`createGroupMotion` — each 模式

### 5.1 API 设计

```ts
function createGroupMotion(signal, keyFn?, context?): [visibleItems, GroupMotion];
```

- `signal`：业务数组信号的 getter
- `keyFn`（可选）：身份标识函数，与 `each` 的 `key` 保持一致。不传则走全量退出
- `context`（可选）
- 返回：
  - `visibleItems`：动画信号（派生自 `signal`，延迟更新），绑定到 `each`
  - `GroupMotion`：指令组件

### 5.2 实现骨架（伪代码）

```ts
function createGroupMotion(signal, keyFn, context?) {
  const [getter, setter] = context ? context.use(signal) : use(signal);
  const propsMap = new Map<Element, { from: any; to: any; duration: number }>();
  const keyToElMap = new Map<any, Element>();
  let tick = 0;

  // 动画信号
  const [visibleItems, setVisibleItems] = context ? context.use(signal()) : use(signal());

  // 派生：延迟更新动画信号
  const derived = context ? context.use : use;
  derived(signal, () => {
    const newArray = signal(); // 新值
    const oldArray = visibleItems(); // 旧值（派生触发时尚未更新）
    const myTick = ++tick;

    // 计算延迟（取最大 duration）
    const delay = Math.max(0, ...[...propsMap.values()].map((p) => p.duration)) * 1000;

    // diff 并启动退出动画
    const anims = [];
    if (keyFn) {
      const oldKeys = new Map(oldArray.map((item) => [keyFn(item), item]));
      const newKeys = new Set(newArray.map((item) => keyFn(item)));
      for (const [key, el] of keyToElMap) {
        if (!newKeys.has(key) && oldKeys.has(key)) {
          const p = propsMap.get(el);
          if (p && p.from && getMotionState(el) !== "exiting") {
            setMotionState(el, "exiting");
            anims.push(
              animate(el, p.from, { duration: p.duration }).finished.then(() =>
                setMotionState(el, "exited"),
              ),
            );
          }
        }
      }
    } else {
      // 无 keyFn：全量退出
      for (const [el, p] of propsMap) {
        if (p.from && getMotionState(el) !== "exiting") {
          setMotionState(el, "exiting");
          anims.push(
            animate(el, p.from, { duration: p.duration }).finished.then(() =>
              setMotionState(el, "exited"),
            ),
          );
        }
      }
    }

    // 实际实现中应 await Promise.allSettled(anims) 后再检查 tick
    setTimeout(async () => {
      if (myTick !== tick) return;
      await Promise.allSettled(anims); // 等待动画完成
      if (myTick !== tick) return;
      setVisibleItems(newArray);
    }, delay);
  });

  const GroupMotion = direct((el, props, ctx) => {
    const { from, to, duration = 0.3 } = props;
    propsMap.set(el, { from, to, duration });

    // 记录 key 映射
    if (keyFn && props.key !== undefined) {
      keyToElMap.set(props.key, el);
    }

    // 进入动画
    ctx.onMount(() => {
      if (!to) return;
      setMotionState(el, "entering");
      void animate(el, to, { duration }).finished.then(() => setMotionState(el, "idle"));
    });

    ctx.onUnmount(() => {
      if (keyFn && props.key !== undefined) {
        keyToElMap.delete(props.key);
      }
      propsMap.delete(el);
    });
  });

  return [visibleItems, GroupMotion];
}
```

### 5.3 使用示例

```jsx
function Comp(_, context) {
  const [items] = use([
    { id: 1, text: "A" },
    { id: 2, text: "B" },
    { id: 3, text: "C" },
  ]);
  const keyFn = (v) => v.id;
  const [visibleItems, GroupMotion] = createGroupMotion(items, keyFn, context);

  const removeItem = (id) => {
    items(items().filter((i) => i.id !== id)); // 直接更新业务信号
  };

  return (
    <ul each={visibleItems} key={keyFn}>
      {(item) => (
        <GroupMotion
          key={keyFn(item())}
          from={{ opacity: 0, transform: "translateY(20px)" }}
          to={{ opacity: 1, transform: "translateY(0)" }}
        >
          <li>
            {item().text} <button onClick={() => removeItem(item().id)}>删除</button>
          </li>
        </GroupMotion>
      )}
    </ul>
  );
}
```

### 5.4 关键设计说明

- **旧数组来源**：派生触发时 `visibleItems()` 还未更新，自然保存上一轮的数据。
- **key 映射**：用 `Map<any, Element>` 替代 `dataset`，避免字符串转换和冲突。
- **延迟计算**：同样从 `propsMap` 实时取最大值。
- **退出动画执行**：实际代码中必须 `await Promise.allSettled(anims)`，伪代码中的 `setTimeout` 仅为示意。

## 六、元素状态追踪

通过 `Symbol("kiaao.motion.state")` 在元素上维护状态：`idle` / `entering` / `exiting` / `exited`。在启动退出动画前检查，防止重复触发。

## 七、代际标记

`tick` 自增计数器，派生回调记录生成时序号，异步完成后检查是否过时，确保最终一致性。

## 八、context 可选

传入 `context` 则使用组件级信号，否则使用全局信号，支持模块级共享。

## 十、结论

v4.0 通过 **业务信号与动画信号分离** 彻底解决了“文案等待动画”的问题，同时保持了信号模型的同步性。内部机制复用原有任务收集、延迟管理、状态追踪，仅触发方式从手动 `play` 变为派生自动触发。`createGroupMotion` 支持 key 精确 diff 和无 key 全量退出两种模式。文档明确了旧值来源、key 映射方式、延迟计算策略以及已知局限（如中途反转的动画残留）。整体设计贯彻了 kiaao “机制在核心，策略在扩展”的哲学。
