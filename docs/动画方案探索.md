# 动画方案探索与 Motion 指令实现 v2.0

**状态**：阶段总结 + 实现指南
**关联**：kiaao v4.2 自定义指令系统
**日期**：2026年6月14日

> **声明**：本文档中的代码示例均为示意伪代码，用于说明概念和设计模式。具体实现由开发者根据实际需求自行决定。

## 一、背景

### 1.1 问题的起点

kiaao 希望为开发者提供动画能力，特别是**进入动画**和**退出动画**。进入动画相对简单——元素插入 DOM 时，CSS 的 `animation` 属性会自动触发，JS 动画库可以在元素挂载后调用。但退出动画需要框架在移除 DOM **之前**等待动画完成——否则动画还没播放，元素就已经消失了。

最理想的使用体验是声明式的：

```jsx
<div when={visible}>
  <Motion from={{ opacity: 0 }} to={{ opacity: 1 }}>
    <div class="content">动画内容</div>
  </Motion>
</div>
```

当 `visible` 变为 false 时，框架应等待退出动画播放完毕再移除 DOM。

### 1.2 核心矛盾：异步挂载可行，异步卸载不可行

在 kiaao 中，挂载和卸载的触发点处于框架的不同层级：

|                  | 异步挂载                    | 异步卸载             |
| ---------------- | --------------------------- | -------------------- |
| 触发方           | Promise.then（框架外部）    | 派生回调（框架内部） |
| 与派生回调的关系 | 无关                        | 在派生回调内部       |
| 能否 await       | 能（Promise.then 天然支持） | 不能（派生回调同步） |
| 框架支持         | ✅ 已实现（异步组件）       | ❌ 不可行            |

**根本原因**：`when`/`each` 的 DOM 清理发生在**派生回调**中。派生回调是同步的——信号变化后立即同步执行所有下游派生。如果在 `disposeNode` 中等待退出动画的 Promise，派生回调就需要变成异步——这将破坏 kiaao 响应式系统的核心模型。

## 二、React / Vue / Solid 的退出动画处理方式

### 2.1 React：用户控制时序，库辅助状态管理

React **没有内置的退出动画支持**。社区库通过**延迟状态更新**来实现退出动画——不更新 React 状态，旧 DOM 持续存在，动画完成后才真正移除。

### 2.2 Vue：框架内置，虚拟 DOM 异步提交

Vue 通过 `<Transition>` 提供退出动画支持，依赖虚拟 DOM 的协调阶段和提交阶段的分离。对 kiaao 不适用——kiaao 没有虚拟 DOM。

### 2.3 Solid：应用层组件，信号驱动延迟

Solid 的 `Transition` 组件通过**延迟信号更新**来延长旧 DOM 的寿命。对 kiaao 有参考价值——不是修改框架核心，而是在应用层利用信号系统实现。

### 2.4 三种模式的共同点

> **不要试图在框架核心中等待动画，而是让触发移除的信号延迟更新。**

## 三、方案探索（废弃方案略）

最终方向：**工厂函数模式**——指令收集动画任务，用户控制时序。信号模型保持纯粹，不引入任何框架层面的异步机制。

## 四、工厂函数模式设计：`createMotion(signal, context)`

### 4.1 最终 API 命名

| 概念       | 命名                            | 说明                           |
| ---------- | ------------------------------- | ------------------------------ |
| 工厂函数   | `createMotion(signal, context)` | 接收信号 getter + 组件 context |
| 异步触发器 | `play(value)`                   | 触发动画并等待完成后更新信号   |
| 指令       | `Motion`                        | 挂载到元素上，收集动画任务     |

### 4.2 为什么接收 `(signal, context)`

1. **自动规范化**：工厂函数内部通过 `context.use(signal)` 获取 `[getter, setter]`。用户不需要手动解构 `use`。
2. **自动获取 setter**：不需要用户传入 `setState`，工厂函数内部拿到 setter。
3. **内部可获取值比对**：`play(newValue)` 调用时，内部通过 `getter()` 获取当前值，对比新旧值实现差分。
4. **`context.use` 是推荐方式**：任何时候都推荐使用 `context.use` 定义或派生信号，以保证性能与及时释放。`createMotion` 内部遵循这一原则。
5. **`context.onUnmount`**：工厂函数可注册清理逻辑，组件卸载时自动清理内部状态。

### 4.3 使用方式

```jsx
function Comp(_, context) {
  const [visible] = use(true);
  const [play, Motion] = createMotion(visible, context);

  return (
    <div>
      <button onClick={() => play(false)}>关闭</button>
      <div when={visible}>
        <Motion from={{ opacity: 0 }} to={{ opacity: 1 }}>
          <div class="content">内容</div>
        </Motion>
      </div>
    </div>
  );
}
```

**特点**：

- `play(false)` 触发所有已注册元素的退出动画
- 退出动画完成后，框架更新 `visible` 信号
- `when` 检测到 `visible` 变为 false，同步移除 DOM
- 派生回调保持同步，异步等待全部在用户态 `play` 中完成

## 五、处理快速连续调用：代际标记 + 元素状态追踪

### 5.1 代际标记

维护递增的 `tick` 计数器。每次 `play` 调用时记录 `myTick`，完成后检查是否被后续调用取代。

### 5.2 元素状态追踪

快速连续调用时，某个元素可能正在退出动画中，新的 `play` 调用需要知道这个状态。在元素上通过 Symbol key 做标记：

```ts
const MOTION_STATE = Symbol("kiaao.motion.state");

// 元素状态枚举
// 'idle'      — 空闲，可以进入或退出
// 'entering'  — 正在播放进入动画
// 'exiting'   — 正在播放退出动画
// 'exited'    — 已退出，等待 DOM 移除
```

**优势**：

- 不引入外部 Map 的 GC 问题
- 元素被移除时标记自动消失
- 指令内部可以通过 `el[MOTION_STATE]` 直接读写状态

## 六、数组差分：内置 microdiff

### 6.1 设计决策

Motion 指令内置数组差分逻辑，精确判断哪些元素被移除、新增、移动。只处理数组类型——其他类型（Map、Set、对象等）用户自行转换为数组后再使用。这保证了差分逻辑的稳定性和简洁性。

### 6.2 差分逻辑

`play(newValue)` 被调用时：

1. 通过 `getter()` 获取当前值（旧值）
2. 对比新旧数组，使用 diff 算法得出差异列表
3. 差异列表中标记为 `REMOVE` 的元素 → 触发退出动画
4. 差异列表中标记为 `CREATE` 的元素 → 等待 `setter` 更新后，由 `ctx.onMount` 触发进入动画
5. 差异列表中标记为 `CHANGE` 的元素 → 数据更新，元素保持，不触发动画

**diff 算法核心**：

- 对数组进行顶层比较（不递归比较嵌套对象）
- 返回 `REMOVE`、`CREATE`、`CHANGE` 三种操作类型
- 基于元素的 `data-motion-key` 做身份匹配

### 6.3 实现骨架

```ts
function createMotion(signal, context) {
  const [getter, setter] = context.use(signal);
  const effectMap = new Map(); // element → task 函数
  let tick = 0;

  const play = async (newValue) => {
    const oldValue = getter();
    const myTick = ++tick;

    // 差分
    const diffs = diffArrays(oldValue, newValue);

    // 筛选需要退出的元素
    const removedKeys = new Set(diffs.filter((d) => d.type === "REMOVE").map((d) => d.key));

    // 执行动画任务
    const tasks = [];
    for (const [el, task] of effectMap) {
      const key = el.dataset.motionKey;
      if (key && removedKeys.has(key)) {
        tasks.push(task(newValue, oldValue));
      }
    }

    const results = await Promise.allSettled(tasks);
    if (myTick !== tick) return;

    for (const result of results) {
      if (result.status === "rejected") {
        console.warn("[Motion] animation failed:", result.reason);
      }
    }

    setter(newValue);
  };

  const Motion = direct((el, props, ctx) => {
    const { from, to, duration = 0.3 } = props;

    // 设置 motion-key
    el.dataset.motionKey = props["data-motion-key"] || "";
    el[MOTION_STATE] = "entering";

    // 进入动画
    if (from) Object.assign(el.style, from);
    ctx.onMount(() => {
      animate(el, to, { duration }).finished.then(() => {
        el[MOTION_STATE] = "idle";
      });
    });

    // 动画任务
    const task = (newValue, oldValue) => {
      el[MOTION_STATE] = "exiting";
      return animate(el, from, { duration }).finished.then(() => {
        el[MOTION_STATE] = "exited";
      });
    };

    effectMap.set(el, task);
    ctx.onUnmount(() => {
      effectMap.delete(el);
    });
  });

  return [play, Motion];
}
```

## 七、使用示例

### 7.1 when 模式

```jsx
function Comp(_, context) {
  const [visible] = use(true);
  const [play, Motion] = createMotion(visible, context);

  return (
    <div>
      <button onClick={() => play(!visible())}>Toggle</button>
      <div when={visible}>
        <Motion from={{ opacity: 0 }} to={{ opacity: 1 }}>
          <div class="content">动画内容</div>
        </Motion>
      </div>
    </div>
  );
}
```

### 7.2 each 模式

```jsx
function Comp(_, context) {
  const [items] = use([
    { id: 1, text: "A" },
    { id: 2, text: "B" },
    { id: 3, text: "C" },
  ]);
  const [play, Motion] = createMotion(items, context);

  const removeItem = async (id) => {
    const newItems = items().filter((i) => i.id !== id);
    await play(newItems);
  };

  return (
    <ul each={items} key={(item) => item.id}>
      {(item, index) => (
        <Motion
          from={{ opacity: 0, transform: "translateY(20px)" }}
          to={{ opacity: 1, transform: "translateY(0)" }}
        >
          <li>
            {item().text}
            <button onClick={() => removeItem(item().id)}>删除</button>
          </li>
        </Motion>
      )}
    </ul>
  );
}
```

## 八、后续优化方向

- **移动动画（FLIP）**：在 diff 结果中识别 `CHANGE`（位置移动），添加 FLIP 动画支持
- **`kiaao/motion` 扩展包**：将 `createMotion` 封装为独立扩展
- **微任务调度**：`when`/`each` 的 DOM 变更移至微任务，实现自动批处理

## 九、结论

`createMotion(signal, context)` 统一了 `when` 和 `each` 的动画模式。信号模型保持同步和可预测，不引入任何框架层面的异步机制。内置的数组差分逻辑精确判断元素增删变化，元素状态追踪处理快速连续调用的并发场景。代际标记确保最终状态正确。

这种设计延续了 kiaao 的哲学：**机制在核心，策略在扩展。**
