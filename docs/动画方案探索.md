# 动画方案探索与 Motion 指令实现 v3.0

**状态**：阶段总结 + 实现指南
**关联**：kiaao v4.2 自定义指令系统
**日期**：2026年6月14日

> **声明**：本文档中的代码示例均为示意伪代码，用于说明概念和设计模式。具体实现由开发者根据实际需求自行决定。

## 一、背景

### 1.1 问题的起点

kiaao 希望为开发者提供动画能力，特别是**进入动画**和**退出动画**。进入动画相对简单——元素插入 DOM 时，CSS 的 `animation` 属性会自动触发，JS 动画库可以在元素挂载后调用。但退出动画需要框架在移除 DOM **之前**等待动画完成——否则动画还没播放，元素就已经消失了。

最理想的使用体验是声明式的：

```jsx
<div when={visible}>
  <Motion from={{ opacity: 0 }} to={{ opacity: 1 }}>
    <div class="content">动画内容</div>
  </Motion>
</div>
```

当 `visible` 变为 false 时，框架应等待退出动画播放完毕再移除 DOM。

### 1.2 核心矛盾：异步挂载可行，异步卸载不可行

在 kiaao 中，挂载和卸载的触发点处于框架的不同层级：

|                  | 异步挂载                    | 异步卸载             |
| ---------------- | --------------------------- | -------------------- |
| 触发方           | Promise.then（框架外部）    | 派生回调（框架内部） |
| 与派生回调的关系 | 无关                        | 在派生回调内部       |
| 能否 await       | 能（Promise.then 天然支持） | 不能（派生回调同步） |
| 框架支持         | ✅ 已实现（异步组件）       | ❌ 不可行            |

**根本原因**：`when`/`each` 的 DOM 清理发生在**派生回调**中。派生回调是同步的——信号变化后立即同步执行所有下游派生。如果在 `disposeNode` 中等待退出动画的 Promise，派生回调就需要变成异步——这将破坏 kiaao 响应式系统的核心模型。

## 二、React / Vue / Solid 的退出动画处理方式

### 2.1 React：用户控制时序，库辅助状态管理

React **没有内置的退出动画支持**。社区库通过**延迟状态更新**来实现退出动画——不更新 React 状态，旧 DOM 持续存在，动画完成后才真正移除。

### 2.2 Vue：框架内置，虚拟 DOM 异步提交

Vue 通过 `<Transition>` 提供退出动画支持，依赖虚拟 DOM 的协调阶段和提交阶段的分离。对 kiaao 不适用——kiaao 没有虚拟 DOM。

### 2.3 Solid：应用层组件，信号驱动延迟

Solid 的 `Transition` 组件通过**延迟信号更新**来延长旧 DOM 的寿命。对 kiaao 有参考价值——不是修改框架核心，而是在应用层利用信号系统实现。

### 2.4 三种模式的共同点

> **不要试图在框架核心中等待动画，而是让触发移除的信号延迟更新。**

## 三、方案探索（废弃方案略）

最终方向：**工厂函数模式**——指令收集动画任务，用户控制时序。信号模型保持纯粹，不引入任何框架层面的异步机制。

根据适用场景不同，分离为两个独立的 API：

- **`createMotion`**：处理 `when` 模式（布尔值信号）
- **`createGroupMotion`**：处理 `each` 模式（数组信号）

## 四、`createMotion` — when 模式

### 4.1 API 设计

```ts
function createMotion(signal, context?): [play, Motion];
```

- `signal`：布尔值信号的 getter
- `context`（可选）：组件 context。如果传入，使用 `context.use` 获取组件级信号；否则使用全局 `use`
- 返回 `[play, Motion]`

### 4.2 实现骨架

```ts
function createMotion(signal, context?) {
  const [getter, setter] = context ? context.use(signal) : use(signal);
  const effectMap = new Map(); // element → task 函数
  let tick = 0;

  const play = async (newValue) => {
    const myTick = ++tick;
    const tasks = Array.from(effectMap.values());
    const results = await Promise.allSettled(tasks.map((fn) => fn(newValue)));
    if (myTick !== tick) return;
    for (const r of results) {
      if (r.status === "rejected") console.warn("[Motion] animation failed:", r.reason);
    }
    setter(newValue);
  };

  const Motion = direct((el, props, ctx) => {
    const { from, to, duration = 0.3 } = props;

    // 进入动画
    if (from) Object.assign(el.style, from);
    ctx.onMount(() => {
      el[MOTION_STATE] = "entering";
      animate(el, to, { duration }).finished.then(() => {
        el[MOTION_STATE] = "idle";
      });
    });

    // 退出任务
    const task = (newValue) => {
      // 布尔值：newValue 为 false → 退出
      if (typeof newValue === "boolean" && !newValue) {
        el[MOTION_STATE] = "exiting";
        return animate(el, from, { duration }).finished.then(() => {
          el[MOTION_STATE] = "exited";
        });
      }
      return Promise.resolve();
    };

    effectMap.set(el, task);
    ctx.onUnmount(() => effectMap.delete(el));
  });

  return [play, Motion];
}
```

### 4.3 使用示例

```jsx
function Comp(_, context) {
  const [visible] = use(true);
  const [play, Motion] = createMotion(visible, context);

  return (
    <div>
      <button onClick={() => play(false)}>关闭</button>
      <div when={visible}>
        <Motion from={{ opacity: 0 }} to={{ opacity: 1 }}>
          <div class="content">内容</div>
        </Motion>
      </div>
    </div>
  );
}
```

**流程**：

1. `play(false)` 遍历所有已注册任务，执行退出动画
2. 动画完成后调用 `setter(false)` 更新信号
3. `when` 检测到条件变化，同步移除 DOM
4. 派生回调保持同步，异步等待全部在用户态 `play` 中完成

### 4.4 与 when 映射模式的兼容

`when` 的映射模式对 `createMotion` 完全透明——Motion 只关心它包裹的那个元素，不管元素是在哪种 when 分支中被渲染的：

```jsx
<div when={status} else={<div>Unknown</div>}>
  {{
    success: () => <Motion from={...} to={...}><div/></Motion>,
    error: () => <Motion from={...} to={...}><div/></Motion>,
  }}
</div>
```

## 五、`createGroupMotion` — each 模式

### 5.1 API 设计

```ts
function createGroupMotion(signal, context?): [play, GroupMotion];
```

- `signal`：数组信号的 getter
- `context`（可选）：组件 context
- 返回 `[play, GroupMotion]`

### 5.2 Key 的处理

`GroupMotion` 指令通过 `props.key` 直接接收已计算好的 key 字符串值，设置到 `el.dataset.motionKey` 上。`play` 内部 diff 时，用 `el.dataset.motionKey` 与新旧数组的 key 做匹配。

外部使用 `key` prop 与 `each` 的 `key` 保持一致：

```jsx
const keyFn = (v) => v.id

<ul each={items} key={keyFn}>
  {(item) => (
    <GroupMotion key={keyFn(item())} from={...} to={...}>
      <li>{item().text}</li>
    </GroupMotion>
  )}
</ul>
```

### 5.3 内置数组 Diff

`play(newArray)` 内部对比新旧数组，只对被移除的元素播放退出动画：

```ts
// 内置 diff（伪代码）
function diffArrays(oldArray, newArray, keyFn) {
  const removed = [];
  const oldKeys = new Map(oldArray.map((item) => [keyFn(item), item]));
  const newKeys = new Set(newArray.map((item) => keyFn(item)));

  for (const key of oldKeys.keys()) {
    if (!newKeys.has(key)) removed.push(key);
  }
  return removed;
}
```

### 5.4 实现骨架

```ts
function createGroupMotion(signal, keyFn, context?) {
  const [getter, setter] = context ? context.use(signal) : use(signal);
  const effectMap = new Map();
  let tick = 0;

  const play = async (newArray) => {
    const oldArray = getter();
    const myTick = ++tick;

    // diff：找出被移除的 key
    const removedKeys = new Set(diffArrays(oldArray, newArray, keyFn));

    // 只对移除的元素播放退出动画
    const tasks = [];
    for (const [el, task] of effectMap) {
      const elKey = el.dataset.motionKey;
      if (elKey && removedKeys.has(elKey)) {
        el[MOTION_STATE] = "exiting";
        tasks.push(
          task().then(() => {
            el[MOTION_STATE] = "exited";
          }),
        );
      }
    }

    const results = await Promise.allSettled(tasks);
    if (myTick !== tick) return;
    for (const r of results) {
      if (r.status === "rejected") console.warn("[GroupMotion] animation failed:", r.reason);
    }

    setter(newArray);
  };

  const GroupMotion = direct((el, props, ctx) => {
    const { from, to, duration = 0.3 } = props;

    // 设置 motion-key
    if (props.key !== undefined) {
      el.dataset.motionKey = String(props.key);
    }

    // 进入动画
    if (from) Object.assign(el.style, from);
    ctx.onMount(() => {
      el[MOTION_STATE] = "entering";
      animate(el, to, { duration }).finished.then(() => {
        el[MOTION_STATE] = "idle";
      });
    });

    // 退出任务
    const task = () => animate(el, from, { duration }).finished;
    effectMap.set(el, task);
    ctx.onUnmount(() => effectMap.delete(el));
  });

  return [play, GroupMotion];
}
```

### 5.5 使用示例

```jsx
function Comp(_, context) {
  const [items] = use([
    { id: 1, text: "A" },
    { id: 2, text: "B" },
    { id: 3, text: "C" },
  ]);
  const [play, GroupMotion] = createGroupMotion(items, context);
  const keyFn = (v) => v.id;

  const removeItem = async (id) => {
    const newItems = items().filter((i) => i.id !== id);
    await play(newItems);
  };

  return (
    <ul each={items} key={keyFn}>
      {(item) => (
        <GroupMotion
          key={keyFn(item())}
          from={{ opacity: 0, transform: "translateY(20px)" }}
          to={{ opacity: 1, transform: "translateY(0)" }}
        >
          <li>
            {item().text}
            <button onClick={() => removeItem(item().id)}>删除</button>
          </li>
        </GroupMotion>
      )}
    </ul>
  );
}
```

**流程**：

1. `removeItem(id)` 计算移除后的新数组
2. `play(newItems)` 调用 diff，识别被移除的 key
3. 只对被移除的元素播放退出动画
4. 所有退出动画完成后，`setter(newItems)` 更新信号
5. `each` 检测到数组变化，移除对应 DOM
6. 新增元素的进入动画由 `ctx.onMount` 自然触发

## 六、元素状态追踪

在元素上通过 Symbol key 追踪动画状态：

```ts
const MOTION_STATE = Symbol("kiaao.motion.state");

// 状态枚举：
// 'idle'      — 空闲
// 'entering'  — 正在进入
// 'exiting'   — 正在退出
// 'exited'    — 已退出
```

`play` 调用时，先通过 `el[MOTION_STATE]` 检查状态，避免重复触发。

## 七、代际标记

维护递增的 `tick` 计数器。每次 `play` 调用时记录 `myTick`，完成后检查是否被后续调用取代。确保快速连续调用时的最终状态正确。

## 八、context 参数的可选性

`context` 改为可选参数：

- **有 context**：使用 `context.use(signal)` 获取组件级信号，组件卸载时自动清理
- **无 context**：使用全局 `use(signal)` 返回已有信号引用

这支持了模块级共享动画信号的使用场景。

## 九、后续优化方向

- **移动动画（FLIP）**：在 diff 结果中识别位置移动，添加 FLIP 动画支持
- **`kiaao/motion` 扩展包**：将 `createMotion` 和 `createGroupMotion` 封装为独立扩展
- **微任务调度**：`when`/`each` 的 DOM 变更移至微任务，实现自动批处理

## 十、结论

`createMotion` 和 `createGroupMotion` 分别处理 `when` 和 `each` 的动画场景。信号模型保持同步和可预测，不引入任何框架层面的异步机制。内置的数组 diff 精确判断元素增删，元素状态追踪处理并发场景，代际标记确保最终状态正确。

**Key 的处理**：`GroupMotion` 通过 `props.key` 直接接收计算好的 key 字符串值，与 `each` 的 `key` prop 使用相同的 `keyFn`，保证一致性。

这种设计延续了 kiaao 的哲学：**机制在核心，策略在扩展。**
