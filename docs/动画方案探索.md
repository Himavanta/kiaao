# 动画方案探索 — 讨论记录

**状态**：阶段总结
**关联**：kiaao v4.2 自定义指令系统
**日期**：2026年6月14日

## 一、初始目标

为 kiaao 引入动画能力，特别是**进入动画**和**退出动画**。进入动画可在元素插入 DOM 时自动播放（CSS 或 JS 均可），但退出动画必须在元素被移除 DOM **之前**播放，这需要框架在移除元素时提供等待机制。

理想的使用体验：

```jsx
<div when={visible}>
  <Motion from={{ opacity: 0 }} to={{ opacity: 1 }}>
    <div class="content">动画内容</div>
  </Motion>
</div>
```

当 `visible` 变为 false 时，框架应等待退出动画播放完毕再移除 DOM。

## 二、方案探索

### 2.1 框架等待 Promise

指令的 `onUnmount` 返回 Promise，`disposeNode` 变成异步函数，等待 Promise 完成后再移除元素。

**核心矛盾**：`when` 和 `each` 的 DOM 清理发生在**派生回调**中，派生回调是同步的，无法 `await`。将派生回调改为异步会破坏 kiaao 响应式系统的核心模型。

### 2.2 Abort 机制

框架不等待 Promise，而是通过 `AbortController` 主动中止动画，然后立即移除元素。

**问题**：退出动画被中止后不可见，用户期望的“优雅退出”无法实现。本质上放弃了框架层面的退出动画支持。

### 2.3 Fire-and-Forget 异步移除

`disposeNode` 保持同步，但当 `onUnmount` 返回 Promise 且元素是直接卸载目标时，不立即移除元素，而是注册一个 Promise 回调在动画完成后移除。

```ts
if (result instanceof Promise && el === root) {
  result.finally(() => el.remove());
}
```

**问题**：`clearChildren` 不再可靠——容器在插入新内容前不能保证为空。新旧元素可能并存，需要额外的舞台管理（如将旧元素移出正常流），复杂度显著增加。

### 2.4 用户手动控制时序

退出动画的时序完全由用户在框架外部控制：先播放动画，再改变信号值。

```js
async function handleClose() {
  await playExitAnimation(el);
  setVisible(false);
}
```

框架只提供元素级生命周期钩子（`onMount`/`onUnmount`），不参与动画时序。进入动画由 `onMount` 自然支持，退出动画的资源清理由 `onUnmount` 处理。

## 三、核心矛盾

**派生回调的同步性** vs **退出动画的异步等待**，是本次探索的根问题。

kiaao 的响应式系统建立在同步执行之上：信号变化 → 立即执行派生回调 → 同步更新 DOM。一旦 `disposeNode` 需要异步等待，`when`/`each` 的清理流程就必须异步化，进而要求派生回调异步化——这是对框架核心架构的根本性改变。

任何试图在框架层面“自动等待退出动画”的方案，都无法绕开这一矛盾。

## 四、当前阶段结论

**自定义指令系统提供元素级生命周期钩子，退出动画由用户控制时序。**

指令系统的核心价值：

- **`context.onMount`**：元素插入 DOM 后触发，自然支持 JS 进入动画
- **`context.onUnmount`**：元素被移除前同步触发，用于资源清理（事件监听、Observer、定时器等）
- **`context.use`**：元素级信号，随元素生命周期自动清理

退出动画的推荐模式：

- 用户在改变 `when`/`each` 条件之前，手动播放退出动画
- 动画库（如 Motion）可在 `onMount`/`onUnmount` 中挂载/清理动画实例，但时序由用户控制
- 这是 React 社区的常见模式，开发者已适应

## 五、后续探索方向

以下方向已在讨论中涉及，但未在当前版本采纳，记录备查：

### 5.1 微任务调度（方向 A）

`when`/`each` 的 DOM 变更从派生回调中移至微任务中异步执行。派生回调只做标记，实际 DOM 操作在 `queueMicrotask` 中完成。这从根本上解决同步/异步冲突，但会改变 kiaao 的 DOM 更新语义（从同步变为异步）。

### 5.2 框架层 Abort 支持

为指令的 `onUnmount` 提供 `AbortSignal`，框架可在特定场景（如快速切换）下主动中止动画。不影响用户手动控制时序的主流用法。

### 5.3 退出动画的声明式 API

探索一种不影响派生回调同步性的声明式退出动画 API，让用户在不改变控制时序的前提下获得更好的开发体验。
