# memo 特性设计（未来规划）

## 背景

在 kiaao 中，`when` 指令的惰性函数会在依赖变化时重新执行，并替换宿主元素内的 DOM。某些场景下，我们希望更细粒度地控制 DOM 的更新：即使依赖变化，如果某些关键值没有改变，也应该跳过更新，保留现有 DOM。

`RouterView` 通过内部 `SKIP_UPDATE` 机制解决了嵌套路由的布局保持问题。这个机制揭示了一个通用模式：**惰性函数可以根据关键值的比较结果，决定是否跳过 DOM 更新**。将这一模式提炼为框架的公开特性，可以极大地增强组件库开发者的优化能力。

## 设计草案

### memo 属性

为 `when` 指令（以及可能的 `each`）增加一个可选的 `memo` 属性。`memo` 可以是一个无参函数，每次惰性函数重新执行前，`when` 会调用 `memo` 函数获取当前值，并与上一次的值进行浅比较（`!==`）。如果值没有变化，则跳过清理旧 DOM 和插入新 DOM 的步骤，直接保留现有内容。

### 使用示例

```tsx
// 仅当 userId 真正变化时才重建 ExpensiveComponent
<div when={isLoggedIn} memo={() => userId()}>
  {() => <ExpensiveComponent userId={userId()} />}
</div>
```

在这个例子中，`when` 条件满足（`isLoggedIn` 为真），但惰性函数是否重建内容取决于 `memo` 的返回值：如果 `userId` 没有变化，即使其他依赖变化导致惰性函数重新执行，框架也会跳过更新。

### 内部机制

`memo` 的实现与 `SKIP_UPDATE` 共享相同的底层逻辑：

- `when` 指令中维护 `lastMemoValue`。
- 在 `effect` 回调中，如果存在 `memo` 函数，先调用它获取 `currentMemoValue`。
- 若 `currentMemoValue === lastMemoValue`，则跳过 DOM 更新，返回 `SKIP_UPDATE` 给内部的惰性函数处理流程。
- 否则更新 `lastMemoValue`，并正常执行惰性函数更新 DOM。

### 适用场景

- **条件渲染优化**：昂贵组件的重建仅依赖于特定数据，而非所有被追踪的信号。
- **列表项内部更新控制**：结合 `each` 使用，避免列表项在父数据变化时无意义的重建（需要 `each` 支持 `memo`）。
- **第三方组件库**：为动画库、拖拽库等提供“保留 DOM”的能力，是实现复杂交互的基石。

## 当前状态

`memo` 特性目前**尚未公开发布**，仍处于内部设计阶段。框架内部已经通过 `SKIP_UPDATE` 为 `RouterView` 实现了相同的机制，证明其可行性。未来根据社区反馈和实际需求，可能会在 `when` 和 `each` 中正式启用 `memo` 属性，作为开发者可用的通用优化手段。

## 与派生状态（`derive`）的区别

- `derive` 用于**值**的缓存和惰性计算，避免重复执行昂贵的计算逻辑。
- `memo` 用于**DOM 结构**的保留，避免不必要的 DOM 销毁和重建，保持元素状态（焦点、滚动位置等）。

两者相辅相成，共同构成 kiaao 的响应式优化体系。
