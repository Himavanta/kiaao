## 总体目标

本次重构是**彻底的破坏性重构**，不考虑任何兼容或过渡路径。一次性将 kiaao 的生命周期管理从「DOM 绑定」迁移到「Owner 树」，同时完成 `h()` 数组化、adapter 抽象、`createApp` API 变更三个核心范式转移。

### 最终目录结构

```
src/
  index.ts              # 公开 API 入口
  core/                 # 平台无关的核心
    owner.ts            # Owner 数据结构、createOwner、disposeOwner、triggerMount、currentOwner
    signal.ts           # use()、isUse()、toValue()、RenderMode（从 reactive/ 迁入）
    types.ts            # 类型与 Symbol（移除 DOM 绑定的 Symbol）
    h.ts                # h() 路由：组件模式 → handleComponent，DOM 模式 → adapter
    component.ts        # handleComponent、handleAsyncComponent、createContext
    directives.ts       # when / each 指令（Owner 管理）
    direct.ts           # direct() API
    create-app.ts       # createApp API（应用实例管理挂载/卸载）
  dom/                  # 浏览器渲染层
    adapter.ts          # RenderAdapter 接口的浏览器实现
    props.ts            # 属性/事件处理（通过 adapter 操作，从 dom-utils 迁入）
  server/               # SSR 渲染层
    adapter.ts          # RenderAdapter 接口的 SSR 实现（无 DOM 操作）
    render.ts           # renderToString
  motion/               # 动画扩展
    index.ts            # 不变
  router/               # 路由
    index.ts            # 改为通过 adapter 获取 location/history
    utils.ts            # 不变
  astro/                # Astro 集成
    index.ts            # 不变
    client.ts           # 不变
    server.ts           # 不变
  jsx-runtime/          # JSX 运行时
    index.ts            # 适配 h() 新返回类型
  jsx-dev-runtime/      # JSX 开发运行时
    index.ts            # 适配 h() 新返回类型
```

> **来源**：`src/react/` 和 `src/dom/` 被拆解重组。`reactive/types.ts` 中与 DOM 绑定的 Symbol（`INSTANCE_KEY`、`DISPOSE_KEY`、`LOCAL_EFFECTS`、`EFFECTS_KEY`、`INITIALIZED_KEY`、`DISPOSED_KEY`、`DIRECTIVE_MOUNT`、`DIRECTIVE_UNMOUNT`）全部移除。`dom/dom-utils.ts` 中的 DOM 操作迁移到 `dom/adapter.ts` 和 `dom/props.ts`。`dom/local-effect.ts` 移除。`dom/fragment.ts` 不再需要容器，简化。

#### 关键实现细节

**`owner.ts`**：

```ts
interface Owner {
  parent: Owner | null;
  children: Owner[];
  cleanups: (() => void)[];
  mountCallbacks: (() => void)[];
  unmountCallbacks: (() => void)[];
  elements: Set<unknown>;
  disposed: boolean;
}

function createOwner(): Owner;
function disposeOwner(owner: Owner): void;
// → 遍历 children 快照，递归 dispose，清空 children
// → 不要求子节点自行从父节点 splice 移除
function triggerMount(owner: Owner, visited?: Set<Owner>): void;
// → 遍历 mountCallbacks，执行后清空
// → 递归子 Owner
function createCurrentOwner(): { get: () => Owner | null; set: (o: Owner | null) => void };
```

**`RenderAdapter` 接口**：

```ts
interface RenderAdapter {
  createElement(tag: string): unknown;
  createTextNode(text: string): unknown;
  createComment(text: string): unknown;
  insertBefore(parent: unknown, child: unknown, ref: unknown | null): void;
  removeElement(el: unknown): void;
  replaceWith(oldNode: unknown, ...newNodes: unknown[]): void;
  setAttribute(el: unknown, key: string, value: string): void;
  removeAttribute(el: unknown, key: string): void;
  addEventListener(el: unknown, type: string, handler: Function): void;
  removeEventListener(el: unknown, type: string, handler: Function): void;
  setProperty(el: unknown, key: string, value: unknown): void;
}
```

#### 测试覆盖

| 测试                                                             | 说明                                                                                      |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Owner 创建与父子关系                                             | `createOwner` → 添加子 Owner → 验证 `parent`/`children` 双向指向                          |
| `disposeOwner` 清理顺序                                          | 验证 cleanups 先于 elements 移除，子 Owner 先于自身                                       |
| `disposeOwner` 子 Owner 遍历正确性                               | 3 个子 Owner → `[...owner.children]` 快照 → `splice` 其中一个 → 验证全部 3 个仍被 dispose |

#### 关键实现细节

**`h()` 组件模式**（`src/core/h.ts` 中的 `handleComponent`）：

```ts
function handleComponent(tag, props) {
  const owner = createOwner();
  const parentOwner = currentOwner.get();
  if (parentOwner) {
    parentOwner.children.push(owner);
    owner.parent = parentOwner;
  }

  const context = createContext(owner);
  // context.onMount → owner.mountCallbacks
  // context.onUnmount → owner.unmountCallbacks
  // context.use → owner.cleanups

  const prevOwner = currentOwner.get();
  currentOwner.set(owner);
  const result = tag(props, context);
  currentOwner.set(prevOwner);

  if (result instanceof Promise) {
    return handleAsyncComponent(result, owner, context);
  }

  const nodes = Array.isArray(result) ? result.flat(Infinity) : [result];
  nodes.forEach((n) => {
    if (n instanceof Node) owner.elements.add(n);
  });
  return nodes; // Node[]
}
```

**`h()` DOM 模式**（`src/core/h.ts` 中的 `handleDomMode`）：

```ts
function handleDomMode(tag, props, children) {
  const adapter = getAdapter();
  const el = adapter.createElement(tag);

  if (props) setProps(el, props);

  const childNodes = processChildren(children);
  for (const node of childNodes) {
    adapter.insertBefore(el, node, null); // append
  }

  return [el]; // Node[]
}
```

**指令模式**：同当前，返回 children 数组。

**Fragment**：直接返回 `children` 参数扁平化后的数组，不创建任何容器节点。

| ------------------------------------ | --------------------------------------------------------- |

  if (currentBranchOwner) {
    disposeOwner(currentBranchOwner);

  currentBranchOwner = createOwner();
  currentBranchOwner.parent = containerOwner;

**`each` 条目 Owner**（`directives.ts`）：

// 旧：ctx.onMount(fn) → el[DIRECTIVE_MOUNT].add(fn)

function createApp(component, props?) {
  const rootOwner = createOwner();

  currentOwner.set(rootOwner);

  currentOwner.set(null);

  return {
    mount(container) {
      const target = typeof container === "string" ? document.querySelector(container) : container;
      target.append(...nodes);
      triggerMount(rootOwner);
    },
    unmount() {
      disposeOwner(rootOwner);
    },
  };
}

**依赖**：阶段三（adapter 接口）、阶段五（API 清理）

**范围**：实现 SSR 专用的 `RenderAdapter`，更新 `renderToString`。

#### 文件清单

| 文件                    | 动作 | 内容                                                                                  |
| ----------------------- | ---- | ------------------------------------------------------------------------------------- |
| `src/server/adapter.ts` | 新建 | `RenderAdapter` 的 SSR 实现：`createElement` 返回序列化结构，`removeElement` 为空操作 |
| `src/server/render.ts`  | 重写 | `renderToString` 使用 SSR adapter                                                     |

#### SSR Adapter 实现要点

```ts
const serverAdapter: RenderAdapter = {
  createElement(tag) {
    return { type: "element", tag, attrs: {}, children: [] };
  },
  createTextNode(text) {
    return { type: "text", value: text };
  },
  createComment(text) {
    return { type: "comment", value: text };
  },
  removeElement() {
    // SSR 无 DOM，空操作
  },
  // ...
};
```

`renderToString` 结束时遍历 Owner 树 cleanup（仅执行 cleanups，跳过 `removeElement`）。

#### 测试覆盖

| SSR `renderToString` 后 Owner 清理 | 不产生 dangling Owner                |
| SSR 错误处理                       | 异步组件 → 抛出错误                  |

## 注意事项

1. **每个阶段结束后必须通过全部测试才能请求确认。** 测试包括该阶段新建的测试 + 之前所有阶段的测试。
2. **极端情况优先**：每个阶段的测试不仅要覆盖正常路径，还要覆盖空值、异常、边界条件。
3. **测试优先于实现**：建议每个模块先写测试，再写实现（TDD 风格）。
4. **Owner 树是正确的基石**：阶段一的正确性直接影响所有后续阶段。`disposeOwner` 的 bug（如 mutation-while-iterating）必须在阶段一彻底消灭。
5. **`currentOwner` 是唯一的全局状态。** 它的 push/pop 时机必须精确。任何在 `currentOwner` 栈不正确时创建的 Owner 都会成为孤儿。
6. **启动时自动注册 browser adapter**：`src/index.ts` 在导入时调用 `setAdapter(browserAdapter)`，确保浏览器端用户无感。
