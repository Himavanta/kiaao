## P0 — 需要优先修复

### 1. disposeOwner 后 DOM 元素未清理

**触发条件**：组件 Owner dispose 后，其 `elements` 中的 DOM 节点应被移出 DOM 树。

```
测试: dispose-owner.test.ts > elements are removed from DOM after dispose
```

**框架响应**：部分场景下 `removeNode(el)` 未能将元素移出父容器。因为 `handleDomMode` 返回的 HResult `owner = null`，没有任何 Owner 跟踪该元素。`disposeOwner(result.owner!)` 中 `owner` 是 `null`，`null.elements` 是空集 → 元素永远不被移除。

**关联根因**：`handleDomMode` 返回 `createHResult(null, [el])` —— 元素没有挂到任何 Owner 上。这是 `nestBind` 架构设计的结果（DOM 元素不创建 Owner）。

**是否修复**：否（设计如此，需确认是否要改）

---

### 2. dispose 后信号订阅未停止

**触发条件**：Owner dispose 后，其 `cleanups` 中的信号绑定 stop 函数应被调用，停止派生追踪。

```
测试: lifecycle.test.ts > lifecycle — dispose guard > signal subscription stops after dispose
测试: dispose-owner.test.ts > disposeOwner — idempotence > signal subscriptions are cleaned up on dispose
```

**框架响应**：`subscribeSignal` 创建的派生注册了 `state.stop` 到 `owner.cleanups`，`disposeOwner` 执行 `cleanups` 时调用了 stop。但某些路径下派生仍会响应信号变化（如 `use()` 在全局 scope 创建的派生未注册 stop 到任何 Owner）。

**是否修复**：否（需要排查具体路径）

---

### 3. `nestBindPrimitive` 不处理 `true` 值

**触发条件**：`true` 作为 `h()` 的 children 传入。

```
测试: h-defense.test.ts > null/undefined are filtered, true renders as text
```

**框架响应**：`nestBindPrimitive` 只过滤 `isNil`（null/undefined），`true` 进入 `String(true)` → `"true"` 文本节点。用户明确表示 `true` 不需要过滤，但渲染为 "true" 文本可能不是预期行为。JSX 中 `{true}` 通常被理解为无输出。

**是否修复**：视行为定义而定

## 第二轮测试（2026-06-27）

### 11. adapter.remove(null/undefined) 崩溃

**触发条件**：`adapter.remove(null)` 或 `adapter.remove(undefined)`

```
测试: adapter-edge.test.ts > remove null/undefined does not crash
```

**框架响应**：`removeNode(null)` → `_adapter?.remove(null)` → `(null as ChildNode).remove()` → 类型错误。

**直接原因**：`removeNode` 函数没有对参数做 null 检查。

### 12. adapter.append(textNode, child) 崩溃

**触发条件**：向文本节点 append 子节点

```
测试: adapter-edge.test.ts > append to text node does not crash
```

**框架响应**：`parent.append(child)` 在 Text 节点上抛出 DOMException。

**直接原因**：DOM adapter 的 `append` 没有判断 parent 类型。

### 13. adapter.clear(textNode) 崩溃

**触发条件**：对文本节点调用 clear

```
测试: adapter-edge.test.ts > clear on text node does not crash
```

**框架响应**：`(textNode as Element).replaceChildren()` 抛出 TypeError。

**直接原因**：DOM adapter 的 `clear` 没有判断 parent 类型。

### 14. 指令抛异常未被框架捕获

**触发条件**：指令函数内 `throw`

```
测试: directive-edge.test.ts > directive that throws does not crash
```

**框架响应**：异常传播到 `handleDirectiveMode` 之外，未被 try/catch 兜底。

**直接原因**：`handleDirectiveMode` 中的指令调用没有 try/catch。

### 15. 指令嵌套时 onMount 顺序错误

**触发条件**：指令 A 包含指令 B

```
测试: directive-edge.test.ts > directive inside directive renders both
```

**框架响应**：预期 `["inner", "outer"]` 但得到空数组或不同顺序。

### 16. onUnmount 在 dispose 后未触发

**触发条件**：组件 dispose 后指令的 onUnmount 未执行

```
测试: directive-edge.test.ts > onUnmount fires when parent is disposed
```

**框架响应**：`directiveOwner` 可能未正确连接到 Owner 树，导致 `disposeOwner` 遍历不到它。

### 17. 信号订阅清理未生效（内存泄漏）

**触发条件**：1000 次 create + dispose 后，信号值变化仍触发所有已清理的派生

```
测试: memory-leak.test.ts > 1000 Show toggle does not leak signal subscriptions
memory-leak.test.ts > signal sub set size does not grow
```

**框架响应**：`fireCount` 从 1000（初始计算）增长到 2000，说明 `sig(42)` 触发了全部 1000 个派生，即使它们的 stop 已在 `disposeOwner` 中被调用。**信号停止函数未生效。**

**严重性**：P0 — 每次 Show/Each 切换都会泄漏一个信号绑定。

### 18. 深层组件树 dispose 后 DOM 残留

**触发条件**：30 层组件嵌套后 dispose

```
测试: memory-leak.test.ts > component tree depth 30 disposes cleanly
```

**框架响应**：`disposeOwner(result.owner!)` 后部分 DOM 节点仍在容器中。

## 修复进度

### 2026-06-27 修复：信号泄漏（分组 A）

**发现**：所有测试使用了 `Symbol.for("reactive")`（全局 Symbol），但框架使用 `Symbol("reactive")`（局部 Symbol）。两者完全不同，`getSignalState` 返回 `undefined`，stop 从未注册到 owner.cleanups。

**修复**：将测试中的 `(derived as any)[Symbol.for("reactive")]` 替换为 `getSignalState(derived)!`。

**效果**：4 个信号泄漏测试全过。失败总数 75 → 46。

**触发条件**：Portal 在 `() => show() ? \<Portal> : null` 函数子中切换时，onUnmount 清理未执行
**框架响应**：Portal 返回轻量 Owner，函数子切换时 dispose 级联未触发 onUnmount

**是否修复**：否（标记 `test.todo` — 需 Owner 链设计调整）

#### 33. Portal 返回 `owner = null` 导致 nestBindResult 崩溃

**是否修复**：是

#### 34. Portal 内信号绑定不生效
