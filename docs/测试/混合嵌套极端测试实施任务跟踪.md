## 总体策略

按设计文档中的 4 批优先级逐步推进。每批完成后运行全量测试确认无回归。

---

## 第 1 批：Show + Async、Each + Show

### 场景 1：Show + Async

- [ ] Show 内 Async 组件首次渲染显示 placeholder
- [ ] Async resolve 后内容替换 placeholder
- [ ] Show 切到 fallback 时 Async Owner 被 dispose
- [ ] 切回 primary 时 Async 重新创建
- [ ] Async resolve 时 Show 已切到 fallback（竞态）

### 场景 2：Each + Show

- [ ] 列表项内条件渲染每项独立
- [ ] 信号驱动每项切换
- [ ] 列表重排时条件状态保持
- [ ] 列表重排时 dispose 级联正确

---

## 第 2 批：Each + Show + Async、Each + 指令 + Show

### 场景 3：Each + Show + Async

- [ ] 每项独立异步加载
- [ ] 加载完成后各自替换内容
- [ ] 列表重排时项的内部状态保持
- [ ] 列表项 dispose 时未 resolve 的 Promise 不触发

### 场景 4：Each + 指令 + Show

- [ ] 指令在 Each 条目内正常挂载
- [ ] Show 切换时指令 onUnmount 触发
- [ ] 列表重排时指令生命周期正确
- [ ] 指令内信号绑定在 dispose 后停止

## 第 3 批：Async + Each + Show、Portal + Show

### 场景 5：Async + Each + Show

- [ ] 异步组件 resolve 后完整渲染多层嵌套
- [ ] 嵌套内信号绑定工作正常
- [ ] 整个树 dispose 级联正确
- [ ] async resolve 时内部 Owner 已 dispose（不崩溃）

### 场景 6：Portal + Show

- [ ] Show 在 Portal 内正常渲染
- [ ] Show 切换时 Portal 内容更新
- [ ] Portal unmount 时 Show 内容清理
- [ ] Portal 内 Show 的信号绑定工作正常
