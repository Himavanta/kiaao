# 设计决策汇总

**状态**：已锁定
**日期**：2026-07-24

实施前所有设计决策，避免实施过程中反复确认。

## 1. URL 处理

| 维度                   | 决策                                                    | 依据                                        |
| ---------------------- | ------------------------------------------------------- | ------------------------------------------- |
| 末尾斜杠               | 保留字面值，不规范化                                    | kiaao 不做隐式默认行为；URL 字符串是 key    |
| `trailingSlash` option | 不预留                                                  | 暂时不需要；未来如要做作为独立 option       |
| 查询字符串 `?`         | `search` 信号单独暴露；`current` 不含 search            | 职责清晰                                    |
| Hash `#`               | 不解析、不响应、不触发 `onRoute`                        | 用户控制；hash 是 fragment 标识，非路由语义 |
| URL 编码               | 使用 `location.pathname` 实际值（已解码），不做额外转换 | 与 `window.location.pathname` 一致          |
| 大小写敏感             | 敏感；不做大小写规范化                                  | 字符串匹配原样                              |
| `base === "/"`         | 合法，等价于不传                                        | 根 RouteGroup 默认 base 为 `/`              |

## 2. 命名

| 项                              | 决策                                               |
| ------------------------------- | -------------------------------------------------- |
| `createRouter()` 返回顶层组件名 | `Router`                                           |
| `RouteGroup`                    | **不导出**，作为内部递归机件                       |
| `RouterView`                    | 通过 props 传给 layout，由 `Router` 内部持有并创建 |

`createRouter` 返回值：

```ts
function createRouter(options: RouterOptions): {
  Router: ComponentFunction; // 顶层入口
  Link: ComponentFunction; // 声明式导航
  push: (path: string) => Promise<void>;
  current: Signal<string>; // pathname，逻辑只读
  search: Signal<Record<string, string>>; // query，逻辑只读
};
```

## 3. 类型

| 维度                  | 决策                                                              |
| --------------------- | ----------------------------------------------------------------- |
| RouteMap 类型严格度   | **A2 宽松**：不强制 `""` 必传，运行时校验                         |
| `defineRoutes()` 工具 | **不单独提供**：校验逻辑内联在 `createRouter` 入口                |
| 函数简写              | 接受：`demo: () => <Demo />` 等价于 `{ "": fn }`                  |
| `RouterOptions` 字段  | `routes`、`onRoute`（无 `fallback`，由 RouterView children 提供） |

```ts
interface RouterOptions {
  routes: RouteMap;
  onRoute?: (to: string, from: string | null) => string | void | Promise<string | void>;
}
```

## 4. `onRoute` 行为

| 场景            | 行为                                                                                         |
| --------------- | -------------------------------------------------------------------------------------------- |
| `push` 流程     | `onRoute(to, from)` 通过 → `pushState` + 更新信号；reject/throw → `console.error` + 取消导航 |
| `popstate` 流程 | `onRoute(to, from)` 通过 → `replaceState` + 更新信号；reject/throw → 回滚到原 URL            |
| 首次进入        | `onRoute(initialPath, null)` → `replaceState`；reject → 保持初始 URL 不变                    |
| 返回值          | `void` 放行；`string` 重定向（再次进入 `onRoute`）；`Promise` 异步决策                       |
| 重定向链软上限  | 10 次                                                                                        |

## 5. Link 类型

| 项             | 决策                       |
| -------------- | -------------------------- |
| `to` 类型      | `string \| Signal<string>` |
| `onClick` 拦截 | 阻止默认行为后调用 `push`  |

## 6. 并发 push 竞态

不处理。文档明确写：

- 快速连续 `push("/a"); push("/b")` 都会触发 `onRoute`；
- 最终状态是后一个 `onRoute` 完成后的结果；
- 中间态可能闪烁。

## 7. 提取 segment

复用 v1 `extractSegment` 实现，逻辑一致：

- `base` 不存在或为 `/`：匹配所有路径；
- 否则验证 `startsWith` + 边界斜杠检查；
- 取相对路径第一段作为 segment。
