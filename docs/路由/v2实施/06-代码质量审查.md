# v2 代码质量审查

**状态**：已完成
**日期**：2026-07-24

实施 v2 后、铺完整测试前的代码质量检查。已全部修复。

## 高优先级

### 1. 临时冒烟测试文件未清理

`tests/router/v2-smoke.test.ts` 已被删除（验证通过后）。正式 router 测试会直接写为 `router.test.ts` 与 `router-extreme.test.ts`，无需保留冒烟。

### 2. 重复的导航 while 循环

`router.ts` 中 push / popstate / 首次进入 三个流程都用了同样的 while 循环 + runGuard 模式：

```ts
while (true) {
  const result = await runGuard(target, from, redirects);
  if ("error" in result) { ... }
  if (result.target !== target || result.next !== redirects) {
    target = result.target;
    redirects = result.next;
    continue;
  }
  // 写入 history + _url
  return;
}
```

三处副本近 80 行。差别只在 error 处理（push 抛错、popstate 回滚、首次进入静默）和 history 写入方式（pushState vs replaceState vs 仅 update）。

可以抽出一个统一的 `navigate(...)` 内部函数接收模式参数。

### 3. `as any` 出现 3 处

- `route-group.ts:61` — `h(Case as any, { value: segment }, others, fallback)`
- `link.ts:38,49` — `h("a" as any, ...)`
- 测试中也用 `as any`

根因是 `h()` 的 overloads 严格，需要 props 字段完整且类型匹配。

- 方案 A：扩展 `h()` 的 overload，允许控制流组件用更宽松的 props
- 方案 B：把 h() 的内置指令/组件专用 `h(tag, props, ...children)` 重载扩展，添加 `(tag: any, props, ...children)` 的最终重载
- 方案 C：保持现状 + 注释说明

倾向 B：这是 kiaao h() 已知的小限制，可以接受一个 `(tag: ComponentFunction, props: object, ...children: any[])` 的通用重载。

## 中优先级

### 4. 对外导出过多

`src/router/index.ts`：

```ts
export { createRouter } from "./router.ts";
export { createRouterLink } from "./link.ts"; // 用户不需要
export type { Router, RouterOptions, RouteMap, RouterLinkProps } from "./types.ts";
```

`createRouterLink` 是内部辅助，外部用不到。`createRouterLink` 不应导出。

`types.ts` 内部类型 `RouteGroupProps` 不应导出（已经加 `export` 是失误，移除）。

倾向：仅导出用户需要的：`createRouter` 和四个类型。

### 5. router.ts 偏大（172 行）

`router.ts` 包含：

- 运行时校验（15 行）
- 信号创建（12 行）
- 三个导航流程（约 100 行）
- Router 组件 + Link 组件创建（10 行）
- 对外契约（5 行）

可以将信号创建与导航流程拆到独立文件 `navigator.ts`，router.ts 只负责对外契约。

倾向：拆分。但不强制，文件 172 行不算大。

### 6. 判别联合类型不够优雅

`runGuard` 返回：

```ts
{ ok: true; target: string; next: number } | { error: true }
```

`ok: true` 字段冗余——直接用 `{ ok: true, ... }` 和 `{ ok: false, ... }` 模式更对称。

倾向：改为：

```ts
type GuardResult = { ok: true; target: string; next: number } | { ok: false };
```

提取到 types.ts。

## 低优先级

### 7. JSDoc 缺失

- `push` 内部函数
- `validateRoutes`
- `createRouterGroup`（仅文件头注释）
- `createRouterLink`

部分函数对外行为关键（特别是 `push` 抛错 vs 静默回滚），值得加 JSDoc 说明。

倾向：补充关键函数 JSDoc，但不为每个内部辅助都加。

## 修复记录

所有问题已修复，总结如下：

| 问题                         | 处理                                                        |
| ---------------------------- | ----------------------------------------------------------- |
| popstate 监听泄漏            | remove + re-add                                             |
| pushState 异常包装           | try-catch 含 `[kiaao]` 前缀                                 |

| `window.location` 裸读       | 收敛到 `getCurrentPath()` / `resolveUrl()`                  |
