# 测试策略

**状态**：进行中
**日期**：2026-07-24

## 目标

保证 v2 实现与 v1 行为等价，同时验证 v2 新增的能力（嵌套对象路由、`""` layout、逻辑只读信号等）。

## v1 测试的角色

v1 测试文件已备份到 `tests/router/v1/`，作为**行为相等性档案**：

- 不在 `vp test` 默认运行时执行；
- 实施 v2 期间，手动用 `vp test tests/router/v1/...` 跑一遍，列出每个测试描述的行为；
- 这些行为要么：
  - 在 v2 测试中保留（API 不同，行为相同）
  - 在 v2 中不再适用（API 变了，无法直接保留）
  - 需要新增行为覆盖（v2 独有）

## 测试覆盖范围

### 必须覆盖

- 嵌套对象路由（`""` layout + 子路由）
- 函数简写自动包装为 `{ "": fn }`
- RouterView props 注入
- `<RouterView>{() => fallback}</RouterView>` 局部 fallback
- onRoute 异步 + 重定向链
- 首次进入 / popstate / push 各自的 `onRoute` 时序
- `current` / `search` 是派生只读信号
- `push` 路径保留字面值
- `Link.to` 是字符串 / getter / signal
- 嵌套路由 layout 保留

### 已知限制

- SSR 不覆盖
- 动态路由不覆盖
- 多路由切换的内存泄漏测试按 v1 等价用例改写

## 运行方式

```bash
vp test                          # 默认：跑当前实现 + router 测试
vp test tests/router/v1/...      # 跑 v1 测试（行为相等性参考）
```

## 已知差异

v1 → v2 期间 v1 测试无法直接运行（API 不同），仅作“行为档案”参考。
